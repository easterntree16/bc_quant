7、订单簿数据深度解析：获取订单簿快照、解析买单和卖单、计算市场深度、识别大额挂单

订单簿，说白了就是市场的「实时报价单」。

我刚开始做链上数据分析时，总觉得订单簿数据就是一堆挂单价格和数量，没什么好深挖的。直到有一次，我在Hyperliquid上盯着一笔大额挂单，发现它挂上去又撤掉，反复几次后，市场突然出现了一波剧烈波动。嗯，从那以后，我再也不敢小看订单簿了。

今天，我们就来彻底拆解Hyperliquid的订单簿数据。我会带你从获取快照开始，一步步解析买单和卖单，计算市场深度，最后揪出那些藏在暗处的大额挂单。

7.1 获取订单簿快照

Hyperliquid的订单簿数据，可以通过它的WebSocket接口实时获取。我个人习惯先拿一个快照，再订阅增量更新，这样既能保证数据完整，又不会漏掉任何变化。

获取快照的API端点很简单：

GET https://api.hyperliquid.xyz/info

请求体：
{
    "type": "orderbook",
    "coin": "BTC"
}

返回的数据结构长这样：

{
    "coin": "BTC",
    "time": 1700000000000,
    "bids": [
        [42000.5, 1.2],
        [42000.0, 0.8],
        ...
    ],
    "asks": [
        [42001.0, 1.5],
        [42001.5, 0.6],
        ...
    ]
}

bids是买单，asks是卖单。每个数组里，第一个数是价格，第二个数是数量。

小技巧： 我建议你每次获取快照时，都记录一下时间戳。这样后续计算深度变化时，能精确到毫秒级别。

7.2 解析买单和卖单

拿到数据后，第一件事就是解析。买单和卖单的结构完全一样，但含义相反。

买单（Bids）： 表示有人愿意以某个价格买入。价格从高到低排列，最高的叫「买一价」。

卖单（Asks）： 表示有人愿意以某个价格卖出。价格从低到高排列，最低的叫「卖一价」。

买一价和卖一价之间的差价，就是「点差」。点差越小，说明市场流动性越好。

举个例子：

类型 价格 数量 累计数量
卖单 42001.0 1.5 1.5
卖单 42001.5 0.6 2.1
... ... ... ...
买单 42000.5 1.2 1.2
买单 42000.0 0.8 2.0

你看，买一价是42000.5，卖一价是42001.0，点差只有0.5美元。这说明BTC在这个价位上流动性不错。

核心要点： 解析订单簿时，一定要关注「累计数量」。它能告诉你，如果我想吃掉所有卖单到某个价格，需要花多少钱。

7.3 计算市场深度

市场深度，说白了就是「市场能承受多大的交易量而不引起价格剧烈波动」。

计算深度的方法很简单：从买一价或卖一价开始，逐级累加数量，直到达到某个价格阈值或数量阈值。

我一般会计算两个指标：

  • 1%深度： 从当前价格上下1%范围内，累计有多少买单和卖单。
  • 固定金额深度： 比如，我想知道吃掉10个BTC的卖单，价格会推到多少。

代码实现起来也不复杂：

def calculate_depth(orders, start_price, depth_percent=0.01):
    """
    计算市场深度
    orders: 订单列表，每个元素是 [price, size]
    start_price: 起始价格（买一价或卖一价）
    depth_percent: 深度百分比，默认1%
    """
    total_size = 0
    total_value = 0
    threshold = start_price * (1 + depth_percent)  # 卖单向上算
    
    for price, size in orders:
        if price > threshold:
            break
        total_size += size
        total_value += price * size
    
    return total_size, total_value
注意： 计算深度时，一定要考虑「滑点」。我曾经遇到过，某个币的订单簿看起来深度很好，但实际交易时，因为挂单量太小，价格瞬间就滑出去了。所以，我建议你同时计算「1%深度」和「0.1%深度」，对比着看。

7.4 识别大额挂单

大额挂单，是市场中最值得关注的数据之一。它们往往是「聪明钱」或「做市商」的痕迹。

怎么定义「大额」？没有固定标准。我个人习惯用「中位数挂单量的3倍」作为阈值。比如，所有卖单的中位数是0.5个BTC，那么超过1.5个BTC的挂单，就算大额。

识别出来后，还要分析它的意图：

  • 真实挂单： 挂上去后长时间不动，说明是真的想买或想卖。
  • 虚假挂单： 挂上去几分钟就撤单，可能是为了制造假象，诱导市场。
  • 冰山订单： 只显示一小部分，实际后面还有大量挂单。这种最难识别，需要观察挂单的「撤单-重挂」模式。

我曾经在Hyperliquid上追踪过一个ETH的大额买单。它挂在买二价，数量是正常挂单的10倍。我一开始以为是个大买家，结果它挂了5分钟就撤了。然后价格开始下跌。嗯，这就是典型的「虚假挂单」——挂个大单托市，然后偷偷出货。

避坑指南： 识别大额挂单时，不要只看数量。还要看「挂单时间」和「撤单频率」。如果一个地址频繁挂大单又撤单，大概率是在做市或操纵。

7.5 实战：构建订单簿分析工具

说了这么多，我们来写一个简单的分析工具。它能获取订单簿快照，计算深度，并标记大额挂单。

import requests
import json

def get_orderbook(coin="BTC"):
    url = "https://api.hyperliquid.xyz/info"
    payload = {
        "type": "orderbook",
        "coin": coin
    }
    response = requests.post(url, json=payload)
    return response.json()

def analyze_orderbook(data):
    bids = data["bids"]
    asks = data["asks"]
    
    # 计算中位数挂单量
    all_sizes = [size for _, size in bids + asks]
    median_size = sorted(all_sizes)[len(all_sizes) // 2]
    large_threshold = median_size * 3
    
    # 识别大额挂单
    large_bids = [b for b in bids if b[1] > large_threshold]
    large_asks = [a for a in asks if a[1] > large_threshold]
    
    # 计算1%深度
    best_bid = bids[0][0]
    best_ask = asks[0][0]
    
    bid_depth = calculate_depth(bids, best_bid, 0.01)
    ask_depth = calculate_depth(asks, best_ask, 0.01)
    
    return {
        "large_bids": large_bids,
        "large_asks": large_asks,
        "bid_depth_1pct": bid_depth,
        "ask_depth_1pct": ask_depth,
        "spread": best_ask - best_bid
    }

# 使用示例
data = get_orderbook("BTC")
result = analyze_orderbook(data)
print(f"点差: {result['spread']:.2f}")
print(f"买单1%深度: {result['bid_depth_1pct'][0]:.2f} BTC")
print(f"卖单1%深度: {result['ask_depth_1pct'][0]:.2f} BTC")
print(f"大额买单: {len(result['large_bids'])} 笔")
print(f"大额卖单: {len(result['large_asks'])} 笔")

这个工具虽然简单，但已经能帮你快速了解一个币的订单簿状况了。你想想看，如果每次交易前都跑一遍这个脚本，是不是能避免很多坑？
