第二十六课：自动化交易信号

链上数据最有魅力的地方，就是它能生成真实的交易信号。不是那种「我觉得要涨」的感觉，而是实打实的、可验证的买卖依据。

今天我们就来聊聊，怎么把链上数据变成自动化交易信号。从信号生成、回测框架、执行策略到绩效评估，一条龙讲清楚。

信号生成：从原始数据到交易指令

信号生成是整个链条的第一步。说白了，就是把链上数据翻译成「买」或「卖」的指令。

我个人习惯把信号分成三类：

  • 阈值信号：当某个指标超过或低于设定值时触发。比如「资金费率连续3小时大于0.1%」就做空。
  • 交叉信号：两条线交叉时触发。比如「交易所净流入量」上穿「7日均值」时卖出。
  • 模式信号：识别特定数据模式。比如「大户地址连续增持+交易所余额下降」同时出现。

实战案例：我在Hyperliquid上跑过一个信号，逻辑很简单——当「主动买单量/主动卖单量」的比值超过2.0，且持续5分钟以上，就开多。回测下来胜率62%，但实盘时滑点吃掉不少利润。嗯，这里要注意：信号越简单，越容易过拟合。

代码实现其实不复杂。下面是一个基于Hyperliquid链上数据的信号生成示例：

// 伪代码：信号生成逻辑
function generateSignal(data) {
  const buyVolume = data.aggressiveBuyVolume;
  const sellVolume = data.aggressiveSellVolume;
  const ratio = buyVolume / sellVolume;
  
  // 阈值信号
  if (ratio > 2.0 && data.duration > 300) {
    return { action: 'BUY', confidence: 0.7 };
  }
  
  // 交叉信号
  const shortMA = calculateMA(data.netflow, 7);
  const longMA = calculateMA(data.netflow, 30);
  if (shortMA > longMA && shortMA.previous <= longMA.previous) {
    return { action: 'BUY', confidence: 0.6 };
  }
  
  return { action: 'HOLD', confidence: 0 };
}

信号回测框架：别让历史数据骗了你

回测是信号验证的核心环节。我曾经犯过一个低级错误——用未来数据回测，结果实盘亏得一塌糊涂。你想想看，如果回测时用了「当天收盘价」来计算「当天开盘信号」，那不就是作弊吗？

一个靠谱的回测框架需要满足几个条件：

  • 时间对齐：信号生成时只能使用历史数据，不能「偷看」未来
  • 滑点模拟：链上交易有延迟，必须加入滑点成本
  • 手续费扣除：Hyperliquid的maker/taker费率不同，要精确计算
  • 资金费率影响：永续合约的资金费率会侵蚀利润

避坑指南：我曾经用1分钟K线做回测，结果发现信号在实盘时根本来不及执行。后来改成5分钟K线，效果反而更好。建议你从大周期开始，逐步缩小。

回测框架的核心结构大概是这样：

class BacktestEngine {
  constructor(config) {
    this.initialCapital = config.capital;
    this.feeRate = config.feeRate;
    this.slippage = config.slippage;
    this.data = [];
  }
  
  run(signals) {
    let capital = this.initialCapital;
    let position = 0;
    let trades = [];
    
    for (let i = 0; i < signals.length; i++) {
      const signal = signals[i];
      const price = this.data[i].price;
      
      if (signal.action === 'BUY' && position === 0) {
        const cost = price * (1 + this.slippage);
        position = capital / cost;
        capital = 0;
        trades.push({ time: signal.time, type: 'BUY', price: cost });
      }
      
      if (signal.action === 'SELL' && position > 0) {
        const revenue = price * (1 - this.slippage);
        capital = position * revenue;
        position = 0;
        trades.push({ time: signal.time, type: 'SELL', price: revenue });
      }
    }
    
    return { finalCapital: capital, trades: trades };
  }
}

信号执行策略：从信号到实盘

信号生成好了，回测也通过了，接下来就是实盘执行。这一步最容易出问题。

我个人常用的执行策略有三种：

  1. 立即执行：信号一出现就市价单进场。适合高流动性、低滑点的品种。
  2. 分批执行：把仓位分成3-5份，每隔一段时间进场。适合大资金，能降低冲击成本。
  3. 条件执行：设置限价单，等价格回到合理区间再进场。适合震荡行情。

注意：Hyperliquid的链上交易有确认延迟。信号生成后，到交易上链，再到确认，中间可能有几秒钟的延迟。对于高频策略来说，这几秒可能就是生与死的区别。

执行策略的代码示例：

// 分批执行策略
async function executeInBatches(signal, totalSize, batches) {
  const batchSize = totalSize / batches;
  let filled = 0;
  
  for (let i = 0; i < batches; i++) {
    const order = await placeOrder({
      symbol: signal.symbol,
      side: signal.action,
      size: batchSize,
      type: 'MARKET'
    });
    
    filled += order.filledSize;
    console.log(`Batch ${i+1}/${batches} filled: ${order.filledSize}`);
    
    // 每批之间等待10秒
    await sleep(10000);
  }
  
  return filled;
}

绩效评估：别只看收益率

很多人做回测只看「年化收益率」，这是个大坑。收益率高不代表策略好，可能是运气好，也可能是过拟合。

我评估信号绩效时，会看这几个指标：

指标 说明 理想值
夏普比率 单位风险下的超额收益 > 1.5
最大回撤 账户从峰值到谷底的最大跌幅 < 20%
胜率 盈利交易占总交易的比例 > 50%
盈亏比 平均盈利 / 平均亏损 > 1.5
卡玛比率 年化收益 / 最大回撤 > 2.0

我的经验：胜率低但盈亏比高的策略，往往比胜率高但盈亏比低的策略更稳定。举个例子，一个胜率40%、盈亏比3:1的策略，长期下来比胜率60%、盈亏比1:1的策略赚得多。你想想看，是不是这个道理？

绩效评估的代码实现：

function evaluatePerformance(trades, initialCapital) {
  let capital = initialCapital;
  let peak = initialCapital;
  let maxDrawdown = 0;
  let wins = 0;
  let losses = 0;
  let totalProfit = 0;
  let totalLoss = 0;
  
  for (const trade of trades) {
    const pnl = trade.pnl;
    capital += pnl;
    
    if (pnl > 0) {
      wins++;
      totalProfit += pnl;
    } else {
      losses++;
      totalLoss += Math.abs(pnl);
    }
    
    peak = Math.max(peak, capital);
    const drawdown = (peak - capital) / peak;
    maxDrawdown = Math.max(maxDrawdown, drawdown);
  }
  
  const winRate = wins / (wins + losses);
  const profitFactor = totalProfit / (totalLoss || 1);
  const avgWin = totalProfit / (wins || 1);
  const avgLoss = totalLoss / (losses || 1);
  const riskRewardRatio = avgWin / avgLoss;
  
  return {
    totalReturn: (capital - initialCapital) / initialCapital,
    maxDrawdown: maxDrawdown,
    winRate: winRate,
    profitFactor: profitFactor,
    riskRewardRatio: riskRewardRatio,
    sharpeRatio: calculateSharpe(trades) // 需要额外实现
  };
}
