6、查询账户信息：获取账户余额、查询持仓信息、解析账户历史交易、监控账户变动

账户信息查询，是链上分析最基础的操作。

你想想看，不管你是做交易、做套利，还是单纯想看看某个大户在干嘛，第一步永远是——查账户。我个人习惯，每天开盘前先扫一遍几个关键地址的余额变化，这比看K线图直观多了。

6.1 获取账户余额

Hyperliquid的账户余额，不是简单的「有多少钱」。它分几个层级：

  • 总资产（Total Value）：账户里所有资产的总价值，包括现货、保证金、未实现盈亏。
  • 可用余额（Available Balance）：可以提现或开新仓的部分。
  • 保证金余额（Margin Balance）：用于维持当前持仓的资金。

我用Hyperliquid的API查余额时，一般这么写：

import requests

# Hyperliquid 账户信息查询
address = "0x你的地址"
url = f"https://api.hyperliquid.xyz/info?type=clearinghouseState&user={address}"

response = requests.get(url)
data = response.json()

print("总资产:", data['totalValue'])
print("可用余额:", data['availableBalance'])
print("保证金余额:", data['marginBalance'])
小技巧： 我建议你每次查余额时，顺便拉一下时间戳。因为链上数据有延迟，有时候你看到的余额其实是几秒前的快照。

6.2 查询持仓信息

持仓信息比余额复杂一些。它包含：

  • 每个交易对的头寸大小
  • 开仓均价
  • 未实现盈亏
  • 杠杆倍数
  • 清算价格

我在项目中遇到过一个问题：某个地址显示有大量空单，但清算价格离当前价格很远。后来发现，他用了跨期套利策略，多空对冲了。所以只看单边持仓，容易误判。

查询持仓的代码示例：

# 获取持仓信息
positions_url = f"https://api.hyperliquid.xyz/info?type=spotClearinghouseState&user={address}"
pos_response = requests.get(positions_url)
positions = pos_response.json()

for pos in positions['assetPositions']:
    print(f"交易对: {pos['coin']}")
    print(f"头寸大小: {pos['position']['size']}")
    print(f"开仓均价: {pos['position']['entryPx']}")
    print(f"未实现盈亏: {pos['position']['unrealizedPnl']}")
    print("---")
注意： 持仓信息中的「头寸大小」是带杠杆后的名义价值。比如你有1个BTC的多单，用了10倍杠杆，显示的头寸大小是10个BTC的名义价值。别搞混了。

6.3 解析账户历史交易

历史交易记录，是分析交易策略的宝藏。

你可以从中看出：

  • 这个地址是趋势交易者还是网格交易者？
  • 他喜欢在什么时间交易？
  • 他的胜率如何？
  • 平均持仓时间多长？

我曾经分析过一个地址，发现他每天固定在北京时间晚上8点到10点交易，而且只做ETH。后来我跟踪了三个月，他的胜率高达78%。嗯，这明显是个有经验的交易员。

获取历史交易的API调用：

# 获取历史交易
tx_url = f"https://api.hyperliquid.xyz/info?type=userFills&user={address}"
tx_response = requests.get(tx_url)
trades = tx_response.json()

for trade in trades[:10]:  # 只看最近10笔
    print(f"时间: {trade['time']}")
    print(f"交易对: {trade['coin']}")
    print(f"方向: {'买入' if trade['side'] == 'B' else '卖出'}")
    print(f"数量: {trade['sz']}")
    print(f"价格: {trade['px']}")
    print(f"手续费: {trade['fee']}")
    print("---")
核心指标： 解析历史交易时，我重点关注三个数据：
1. 平均每笔交易金额——判断资金规模
2. 交易频率——判断是高频还是低频
3. 盈亏比——判断策略质量

6.4 监控账户变动

监控账户变动，说白了就是「盯梢」。

你可以监控：

  • 余额变动（大额转入/转出）
  • 持仓变动（开仓/平仓）
  • 清算事件（这个最刺激）

我建议用WebSocket来做实时监控，而不是轮询API。为什么呢？因为轮询有延迟，而且容易触发频率限制。

一个简单的WebSocket监控示例：

import websocket
import json

def on_message(ws, message):
    data = json.loads(message)
    if data['type'] == 'userFill':
        print(f"新交易: {data['data']['coin']} {data['data']['side']} {data['data']['sz']}")

def on_error(ws, error):
    print(f"错误: {error}")

def on_close(ws, close_status_code, close_msg):
    print("连接关闭")

def on_open(ws):
    # 订阅账户变动
    subscribe_msg = {
        "type": "subscribe",
        "channel": "user",
        "user": address
    }
    ws.send(json.dumps(subscribe_msg))

websocket.enableTrace(False)
ws = websocket.WebSocketApp(
    "wss://api.hyperliquid.xyz/ws",
    on_open=on_open,
    on_message=on_message,
    on_error=on_error,
    on_close=on_close
)
ws.run_forever()
避坑指南： 我曾经因为WebSocket重连逻辑没写好，漏掉了两次大额转账。后来我加了心跳检测和自动重连，才稳定下来。记住：生产环境一定要处理断线重连。

实战建议

最后，给你几个实战中的小建议：

  1. 先查余额，再看持仓——余额能告诉你这个地址还有多少弹药，持仓能告诉你他的战场在哪。
  2. 历史交易要批量拉——一次拉1000笔，然后本地做统计分析，比一次拉10笔效率高得多。
  3. 监控要设阈值——不是所有变动都值得关注。我一般只监控超过1 ETH的转账，或者持仓变化超过10%的情况。
  4. 注意API频率限制——Hyperliquid的API有频率限制，别太贪心。我吃过这个亏，被限流后数据断了好几个小时。

嗯，账户信息查询这块，说白了就是「知己知彼」。你把自己的账户查明白了，才能去查别人的。下一层，我们会深入交易对的深度数据，那才是真正赚钱的地方。
