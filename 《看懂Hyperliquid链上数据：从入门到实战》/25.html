第25章：数据API服务开发

说实话，做链上数据分析最头疼的事是什么？

不是分析逻辑写不出来，而是每次都要手动跑脚本、查数据。我刚开始做Hyperliquid数据分析时，每天要重复执行几十次同样的查询，后来实在受不了了，干脆搭了个API服务。嗯，这一章我就把经验分享给你。

为什么需要API服务？

你想想看，你的分析脚本写得再好，别人用不了也是白搭。API服务说白了就是把你的分析能力包装成接口，让其他人或者前端页面能直接调用。

我在项目中遇到过这样的情况：团队里有人想实时监控Hyperliquid的资金费率变化，但每次都要找我跑脚本。后来我搭了个RESTful API，他自己就能调用了，省了我不少事。

核心价值：API服务让数据分析从「一次性脚本」变成「可复用的服务」

Flask搭建API服务

我个人习惯用Flask，轻量、灵活，适合做数据API。当然你也可以用FastAPI，但Flask的生态更成熟，文档也多。

先装依赖：

pip install flask flask-restful flask-limiter flask-cors

一个最简单的API服务长这样：

from flask import Flask, jsonify
from flask_restful import Api, Resource

app = Flask(__name__)
api = Api(app)

class HealthCheck(Resource):
    def get(self):
        return {"status": "ok", "service": "hyperliquid-api"}

api.add_resource(HealthCheck, '/health')

if __name__ == '__main__':
    app.run(debug=True, port=5000)

启动后访问 http://localhost:5000/health，就能看到返回的JSON了。嗯，就是这么简单。

小技巧：开发时用debug=True，但生产环境一定要关掉，不然会暴露敏感信息。

RESTful接口设计

接口设计这块，我踩过不少坑。刚开始我随便起名字，什么/get_data、/query_info，后来自己都分不清了。

RESTful设计有几个基本原则：

  • 资源用名词复数：/positions、/funding_rates
  • HTTP动词表示操作：GET查、POST创建、PUT更新、DELETE删除
  • 版本号放路径里：/v1/positions
  • 查询参数过滤：/positions?symbol=BTC&limit=10

举个例子，Hyperliquid的持仓数据接口：

class Positions(Resource):
    def get(self):
        """获取用户持仓信息"""
        address = request.args.get('address')
        symbol = request.args.get('symbol')
        
        if not address:
            return {"error": "address is required"}, 400
            
        # 这里调用你的分析逻辑
        data = get_positions_from_hyperliquid(address, symbol)
        return jsonify(data)

api.add_resource(Positions, '/v1/positions')

我曾经犯过一个错误：把POST请求当查询用。后来被同事提醒，GET才是幂等的查询操作，POST应该用于创建资源。记住了，查询用GET，别偷懒。

API认证与限流

API搭好了，总不能谁都能随便调吧？尤其是涉及到链上数据，虽然大部分是公开的，但也要防止被恶意调用。

认证方式我推荐用API Key：

from functools import wraps
from flask import request, jsonify

API_KEYS = {"user1": "sk-xxx", "user2": "sk-yyy"}

def require_api_key(f):
    @wraps(f)
    def decorated(*args, **kwargs):
        api_key = request.headers.get('X-API-Key')
        if api_key not in API_KEYS.values():
            return jsonify({"error": "Invalid API Key"}), 401
        return f(*args, **kwargs)
    return decorated

class ProtectedResource(Resource):
    @require_api_key
    def get(self):
        return {"secret_data": "only for authenticated users"}

限流怎么做？我用的是flask-limiter，配置起来很简单：

from flask_limiter import Limiter
from flask_limiter.util import get_remote_address

limiter = Limiter(
    app,
    key_func=get_remote_address,
    default_limits=["200 per day", "50 per hour"]
)

class FundingRates(Resource):
    @limiter.limit("10 per minute")
    def get(self):
        """获取资金费率，每分钟最多10次"""
        rates = get_funding_rates_from_hyperliquid()
        return jsonify(rates)

注意：限流策略要根据你的服务器性能和用户量来调整。我曾经把限流设得太严，结果用户疯狂报错，后来放宽到每分钟30次才解决问题。

API文档生成

接口写好了，没人知道怎么用等于白搭。我见过太多人写API不写文档，结果天天被问「这个参数是什么意思？」

我个人推荐用Flask-RESTful自带的fields模块配合api.doc()装饰器，或者直接用Swagger/OpenAPI规范。

这里用flasgger快速生成Swagger文档：

from flasgger import Swagger, swag_from

swagger = Swagger(app)

class Positions(Resource):
    @swag_from({
        'parameters': [
            {
                'name': 'address',
                'in': 'query',
                'type': 'string',
                'required': True,
                'description': '钱包地址'
            },
            {
                'name': 'symbol',
                'in': 'query',
                'type': 'string',
                'required': False,
                'description': '交易对，如BTC'
            }
        ],
        'responses': {
            '200': {
                'description': '持仓数据列表',
                'schema': {
                    'type': 'array',
                    'items': {
                        'properties': {
                            'symbol': {'type': 'string'},
                            'size': {'type': 'number'},
                            'entry_price': {'type': 'number'}
                        }
                    }
                }
            }
        }
    })
    def get(self):
        # 实际逻辑
        pass

启动服务后访问 /apidocs，就能看到漂亮的Swagger UI界面，可以直接在页面上测试接口。

我的习惯：每次修改接口后，第一时间更新文档注释。不然过两周你自己都忘了这个参数是干嘛的。

完整示例：Hyperliquid资金费率API

把上面所有知识点串起来，一个完整的资金费率API服务：

from flask import Flask, jsonify, request
from flask_restful import Api, Resource
from flask_limiter import Limiter
from flasgger import Swagger
from functools import wraps

app = Flask(__name__)
api = Api(app)
swagger = Swagger(app)

# 限流配置
limiter = Limiter(app, key_func=lambda: request.remote_addr)

# API Key验证
API_KEYS = {"admin": "hl-api-key-2024"}

def require_key(f):
    @wraps(f)
    def wrapper(*args, **kwargs):
        key = request.headers.get('X-API-Key')
        if key not in API_KEYS.values():
            return {"error": "unauthorized"}, 401
        return f(*args, **kwargs)
    return wrapper

class FundingRate(Resource):
    @require_key
    @limiter.limit("30 per minute")
    def get(self):
        """获取Hyperliquid资金费率"""
        symbol = request.args.get('symbol', 'BTC')
        # 这里调用你的链上数据获取逻辑
        data = fetch_funding_rate(symbol)
        return jsonify(data)

api.add_resource(FundingRate, '/v1/funding-rate')

if __name__ == '__main__':
    app.run(host='0.0.0.0', port=5000)

好了，API服务开发的核心内容就这些。记住一个原则：接口是给别人用的，设计时多站在调用方的角度思考。参数命名要直观，返回格式要统一，错误信息要清晰。做到这三点，你的API就不会太差。
