第19章：量化交易数据准备

历史数据回放、因子计算、特征工程、数据清洗与预处理——这几个词听着就头大，对吧？

我刚开始做Hyperliquid链上量化的时候，也踩过不少坑。说实话，数据准备这一步，占了整个量化系统80%的工作量。但很多人偏偏不重视，总想着赶紧跑策略、看收益。结果呢？回测漂亮得像神话，实盘一跑就崩。

今天我就把这块硬骨头掰开了讲。你跟着走一遍，以后就不会在数据上翻车了。

19.1 历史数据回放：你得先有“历史”

量化交易的第一步，就是拿到干净的历史数据。Hyperliquid的链上数据，说白了就是永续合约的订单簿、成交记录、资金费率这些。

我个人习惯用WebSocket直接拉取，然后存到本地。为什么？因为链上数据虽然公开，但直接从节点拉太慢了，而且容易丢包。

核心数据字段（Hyperliquid永续合约）

字段名说明示例值
timestamp时间戳（毫秒）1710000000000
price成交价格3500.12
size成交量（张）1.5
side买卖方向buy / sell
funding_rate资金费率0.0001
open_interest未平仓量12500000

回放的时候，我建议按时间顺序逐笔模拟。别偷懒用K线聚合数据——那会丢失很多微观结构信息。我曾经在回测里用1分钟K线，结果策略在实盘里频繁被滑点吃掉利润。后来改成逐笔回放，才真正对上了。

# 伪代码：历史数据回放核心逻辑
def replay_trades(trade_list):
    for trade in trade_list:
        # 模拟订单簿更新
        update_orderbook(trade['price'], trade['size'], trade['side'])
        # 计算当前持仓盈亏
        pnl = calculate_pnl(trade['price'])
        # 检查是否触发策略信号
        if check_signal(trade):
            execute_order(trade)

小技巧：回放时一定要保留毫秒级精度。Hyperliquid的撮合速度很快，差几毫秒，你的订单可能就排到后面去了。

19.2 因子计算：从原始数据到“信号”

因子，说白了就是能预测价格变动的特征。比如资金费率的变化率、订单簿的深度不平衡、大单成交的冲击成本等等。

我常用的因子分三类：

  • 价格类因子：动量、均值回复、波动率
  • 订单簿类因子：买卖盘口深度差、挂单量变化率
  • 链上类因子：资金费率偏离度、未平仓量变化

举个例子，资金费率因子。Hyperliquid每1小时结算一次资金费率。如果费率突然飙升到0.05%以上，说明多头极度拥挤。这时候做空，胜率往往不错。我在2023年10月那次BTC暴跌前，就靠这个因子提前平了多单。

# 计算资金费率偏离度因子
def calc_funding_deviation(current_rate, historical_rates):
    mean_rate = np.mean(historical_rates[-24:])  # 过去24小时均值
    std_rate = np.std(historical_rates[-24:])
    z_score = (current_rate - mean_rate) / std_rate
    return z_score  # 偏离度越大，信号越强

注意：因子不是越多越好。我见过有人堆了50个因子，回测夏普比率3.0，实盘直接亏成狗。这叫过拟合。一般5-10个有效因子就够了。

19.3 特征工程：让模型“看懂”数据

原始因子是“原材料”，特征工程就是“加工”。你想想看，模型又不是人，它看不懂“资金费率突然变高”这种语义。你得把它变成数值特征。

常用的特征工程方法：

  1. 归一化：把不同量纲的数据缩放到[0,1]区间。比如价格是几万，成交量是几百，不归一化模型会学歪。
  2. 差分：用当前值减去前一个值，得到变化量。比如“资金费率变化”比“资金费率绝对值”更有预测力。
  3. 滚动统计：过去N个周期的均值、标准差、最大值、最小值。我习惯用5、15、60分钟三个窗口。
  4. 时序滞后：把过去几期的值作为新特征。比如用t-1、t-2时刻的资金费率来预测t时刻的价格。
# 特征工程示例：滚动统计 + 滞后特征
def create_features(df):
    # 滚动均值
    df['funding_ma_5'] = df['funding_rate'].rolling(5).mean()
    df['funding_std_15'] = df['funding_rate'].rolling(15).std()
    # 滞后特征
    df['funding_lag_1'] = df['funding_rate'].shift(1)
    df['funding_lag_2'] = df['funding_rate'].shift(2)
    # 差分
    df['funding_diff'] = df['funding_rate'].diff()
    return df.dropna()

避坑指南：做滚动统计时，一定要用shift()避免未来信息泄露。我曾经犯过这个错——用当前时刻的滚动均值去预测当前时刻的价格，回测结果当然漂亮，但实盘根本不可能实现。

19.4 数据清洗与预处理：脏数据是量化的大敌

链上数据有多脏？我举个例子。Hyperliquid偶尔会出现“插针”行情——价格瞬间打到极端值然后立刻回来。如果你不处理，模型会以为这是正常波动，然后做出错误决策。

数据清洗的常规操作：

  • 去重：同一笔成交被重复记录？直接删掉。
  • 缺失值处理：资金费率偶尔会缺失。我一般用前向填充（ffill），或者用插值法补上。
  • 异常值检测：用3倍标准差法或者IQR（四分位距）法。价格偏离均值超过3个标准差的，直接标记为异常。
  • 时间对齐：不同数据源的时间戳可能不一致。比如成交数据是毫秒级，资金费率是小时级。需要统一重采样到同一时间频率。
# 异常值检测：3倍标准差法
def remove_outliers(df, column, threshold=3):
    mean = df[column].mean()
    std = df[column].std()
    df_clean = df[(df[column] > mean - threshold * std) & 
                  (df[column] < mean + threshold * std)]
    return df_clean

警告：别把异常值全删了！有些异常其实是真实的极端行情（比如黑天鹅事件）。我建议单独建一个“异常事件表”，回测时保留这些数据，实盘时再决定是否过滤。

你看，整个流程是线性的。每一步的输出，就是下一步的输入。我建议你刚开始做的时候，每一步都单独写一个函数，方便调试。等流程跑通了，再考虑用pipeline串起来。

总结一下：

  • 历史数据回放：别用K线，用逐笔数据
  • 因子计算：5-10个有效因子足够，别贪多
  • 特征工程：归一化、差分、滚动统计、滞后，四件套搞定
  • 数据清洗：脏数据比没数据更可怕

嗯，这套流程我用了两年多，在Hyperliquid上跑了十几个策略，基本没出过大问题。你照着做，至少能少走半年弯路。
