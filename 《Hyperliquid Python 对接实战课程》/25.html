实战策略（四）：做市商策略——双边报价、库存管理

做市商策略，说白了就是「两边吃价差」。

你同时挂买单和卖单，别人买你的高价，你赚；别人卖给你低价，你也赚。听起来很美好对吧？但现实是，你可能会被单边行情打穿，库存越积越多，最后变成「接盘侠」。

我在 Hyperliquid 上跑做市策略时，踩过不少坑。今天就把核心逻辑和代码实现拆开来讲。

一、做市商的核心逻辑

做市商不是简单的挂单。它需要解决三个问题：

  • 双边报价：同时挂买单和卖单，价差要覆盖手续费
  • 库存管理：不能让某一方向的仓位过大
  • 风险控制：遇到极端行情要能撤单止损

我个人习惯把做市策略分成两层：

  • 报价层：决定挂什么价格、挂多少量
  • 风控层：决定什么时候撤单、什么时候对冲

你想想看，如果只做报价层不做风控，遇到单边行情，你的库存会瞬间失衡。我曾经在 ETH 上吃过这个亏，半小时内库存从 0 变成 10 个 ETH，差点爆仓。

二、双边报价的实现

双边报价的核心是「基准价 + 价差」。基准价可以是中间价，也可以是加权平均价。我一般用订单簿的中间价：

def get_mid_price(orderbook):
    best_bid = float(orderbook['bids'][0][0])
    best_ask = float(orderbook['asks'][0][0])
    return (best_bid + best_ask) / 2

然后根据价差参数，生成买单和卖单的价格：

def generate_quotes(mid_price, spread_bps, tick_size):
    half_spread = mid_price * spread_bps / 10000 / 2
    bid_price = round(mid_price - half_spread, tick_size)
    ask_price = round(mid_price + half_spread, tick_size)
    return bid_price, ask_price

这里有个细节：spread_bps 是价差基点，1 bps = 0.01%。我建议至少设 5-10 bps，否则连手续费都覆盖不了。

提示：Hyperliquid 的 tick_size 是 0.1，但不同币种可能不同。记得从交易所的元数据里获取。

三、库存管理的核心算法

库存管理，说白了就是「偏了要拉回来」。如果你的库存偏多，就降低买单价格、提高卖单价格，鼓励别人买你的货。

我常用的方法是「库存偏移量」：

def adjust_price_by_inventory(base_price, inventory, target_inventory, max_inventory, k=0.1):
    deviation = (inventory - target_inventory) / max_inventory
    adjustment = base_price * deviation * k
    return base_price - adjustment

这个 k 是调整系数。我一般设 0.05-0.2。太大容易导致报价偏离市场，太小又拉不回来。

举个例子：

  • 目标库存 0，最大库存 10
  • 当前库存 +5（偏多）
  • 偏差 = (5 - 0) / 10 = 0.5
  • 调整量 = 基准价 * 0.5 * 0.1 = 基准价的 5%
  • 买单价格降低 5%，卖单价格提高 5%

这样别人更愿意买你的货，你的库存就慢慢降下来了。

注意：库存管理不能太激进。我曾经设 k=0.5，结果报价偏离市场太多，完全成交不了。做市商的核心是「成交」，不是「挂单」。

四、完整的做市策略框架

下面是一个完整的做市策略框架，包含报价生成、库存管理和订单管理：

class MarketMaker:
    def __init__(self, exchange, symbol, spread_bps, max_inventory, k):
        self.exchange = exchange
        self.symbol = symbol
        self.spread_bps = spread_bps
        self.max_inventory = max_inventory
        self.k = k
        self.target_inventory = 0
        self.bid_order = None
        self.ask_order = None

    def update(self):
        # 1. 获取市场数据
        orderbook = self.exchange.get_orderbook(self.symbol)
        position = self.exchange.get_position(self.symbol)
        inventory = position['size'] if position else 0

        # 2. 计算基准价
        mid_price = get_mid_price(orderbook)

        # 3. 库存调整
        adjusted_mid = adjust_price_by_inventory(
            mid_price, inventory,
            self.target_inventory, self.max_inventory, self.k
        )

        # 4. 生成双边报价
        bid_price, ask_price = generate_quotes(
            adjusted_mid, self.spread_bps, 0.1
        )

        # 5. 撤掉旧订单
        if self.bid_order:
            self.exchange.cancel_order(self.bid_order['oid'])
        if self.ask_order:
            self.exchange.cancel_order(self.ask_order['oid'])

        # 6. 挂新订单
        bid_qty = self.calculate_quantity(inventory, 'buy')
        ask_qty = self.calculate_quantity(inventory, 'sell')

        self.bid_order = self.exchange.place_order(
            self.symbol, 'buy', bid_price, bid_qty
        )
        self.ask_order = self.exchange.place_order(
            self.symbol, 'sell', ask_price, ask_qty
        )

    def calculate_quantity(self, inventory, side):
        # 库存偏多时，减少买单量，增加卖单量
        if side == 'buy':
            return max(0.1, 1 - inventory / self.max_inventory)
        else:
            return max(0.1, 1 + inventory / self.max_inventory)

这个框架的核心是 update() 方法，每次循环执行一次。我一般设 1-2 秒的间隔，太快了容易被交易所限流。

五、避坑指南

做市商策略看着简单，但坑不少。我列几个常见的：

  • 手续费陷阱：Hyperliquid 的 maker 手续费是负的，但 taker 手续费不低。如果你的价差太小，成交后反而亏钱。
  • 滑点问题：大行情时，你的订单可能被瞬间吃掉。我建议设一个「最大滑点保护」，超过一定比例就撤单。
  • 库存上限：一定要设库存上限。我曾经忘了设，结果库存堆到 50 个 ETH，差点爆仓。
  • 网络延迟：做市商对延迟敏感。我建议用 WebSocket 而不是 REST API。
核心要点：做市商不是「挂单等成交」，而是「主动管理库存」。库存管理比报价更重要。

六、策略评估指标

怎么判断做市策略好不好？我一般看这几个指标：

指标 说明 理想值
成交率 挂单被成交的比例 30%-60%
价差收益 每笔交易赚的价差 覆盖手续费后有余
库存波动 库存偏离目标的程度 不超过最大库存的 20%
最大回撤 策略净值最大回撤 小于 5%

我个人习惯每天跑一次回测，看看这些指标有没有恶化。如果库存波动突然变大，说明市场可能出问题了。

做市商策略，说白了就是「用时间换空间」。你赚的是流动性溢价，但也要承担库存风险。我个人建议，刚开始跑的时候用小资金、小价差，跑顺了再慢慢加码。
