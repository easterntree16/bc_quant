第十章：下单操作（二）——签名、轮询、取消与修改

好，咱们接着聊下单的事。上一章我们把订单构造和签名讲清楚了，这一章重点说说怎么把订单真正发出去，以及发出去之后怎么盯着它、怎么把它撤回来。

说实话，这部分才是实战中最容易踩坑的地方。我早期在Hyperliquid上做策略时，就吃过订单状态不同步的亏——明明已经成交了，本地还傻傻地挂着限价单，结果又补了一单进去……嗯，那笔亏损我现在还记得。

10.1 签名并发送订单

订单构造好了，签名也生成了，接下来就是发送。Hyperliquid的API端点很简单，就一个 /order。

发送时，你需要把签名后的订单数据打包成JSON，用POST方式发过去。我个人习惯用 requests 库，轻量又好用。

import requests
import json

def send_order(signed_order: dict) -> dict:
    url = "https://api.hyperliquid.xyz/info"
    # 注意：实际发送订单的端点是 /exchange
    url = "https://api.hyperliquid.xyz/exchange"
    
    payload = {
        "action": signed_order,
        "type": "order"
    }
    
    headers = {"Content-Type": "application/json"}
    
    resp = requests.post(url, data=json.dumps(payload), headers=headers)
    return resp.json()

这里有个细节：签名后的订单里必须包含 signature 字段，否则服务端会直接拒绝。我在项目中遇到过有人把签名拼错了位置，结果返回 {"error": "invalid signature"}，排查了半天才发现是字段名大小写问题。

注意：发送订单时，type 字段必须为 "order"。如果你发的是取消订单，则用 "cancel"。别搞混了。

10.2 订单状态轮询

订单发出去之后，它不会立刻成交。尤其是限价单，可能挂在那里几分钟甚至几小时。这时候你就需要轮询它的状态。

Hyperliquid提供了 /orderStatus 接口，可以查询单个订单的状态。我一般这样写：

def poll_order_status(order_id: str, max_retries: int = 10, interval: float = 0.5) -> dict:
    url = "https://api.hyperliquid.xyz/info"
    
    for i in range(max_retries):
        payload = {
            "type": "orderStatus",
            "orderId": order_id
        }
        resp = requests.post(url, json=payload)
        data = resp.json()
        
        status = data.get("status")
        if status in ["filled", "cancelled", "rejected"]:
            return data
        
        time.sleep(interval)
    
    return {"error": "timeout"}

为什么要轮询？说白了，交易所不会主动推给你成交结果。你只能主动去问。我早期做高频策略时，轮询间隔设成了10毫秒，结果被交易所限流了……后来改成200毫秒一次，稳得很。

小技巧：轮询时不要用死循环。设置最大重试次数和超时时间，避免程序卡死。我一般设10次，每次间隔0.5秒，总共5秒超时。

10.3 订单取消

有时候行情突变，你挂的限价单需要立刻撤掉。取消订单和发送订单类似，只是 type 变成 "cancel"。

取消也需要签名。嗯，你没看错——取消订单也要签名。这是为了防止别人恶意撤销你的单子。

def cancel_order(order_id: str, wallet) -> dict:
    # 构造取消请求
    cancel_data = {
        "type": "cancel",
        "orderId": order_id
    }
    
    # 签名
    signature = wallet.sign(cancel_data)
    cancel_data["signature"] = signature
    
    url = "https://api.hyperliquid.xyz/exchange"
    resp = requests.post(url, json=cancel_data)
    return resp.json()

我曾经犯过一个错：取消订单时忘了传 signature，结果返回 {"error": "signature required"}。当时我还以为是网络问题，折腾了半小时才反应过来。

警告：取消订单的签名和下单的签名算法完全一样，但签名的数据内容不同。取消时签的是 {"type": "cancel", "orderId": "xxx"}，别拿下单的签名直接复用。

10.4 订单修改

Hyperliquid目前不支持直接修改订单。如果你想改价格或数量，只能先取消旧订单，再下新订单。

这个逻辑听起来简单，但实现时有个坑：取消和下单之间有时延。如果你取消后立刻下单，旧订单可能还没完全取消成功，新订单就会因为重复而被拒绝。

我一般这样处理：

def modify_order(old_order_id: str, new_price: float, new_size: float, wallet) -> dict:
    # 第一步：取消旧订单
    cancel_result = cancel_order(old_order_id, wallet)
    if cancel_result.get("error"):
        return cancel_result
    
    # 第二步：等待取消确认
    time.sleep(0.3)  # 给交易所一点处理时间
    
    # 第三步：下新订单
    new_order = construct_order(new_price, new_size, wallet)
    return send_order(new_order)

你可能会问：为什么要等0.3秒？其实这个时间是我试出来的。太短了容易冲突，太长了又影响速度。0.3秒是个不错的平衡点。

建议：如果你做高频策略，可以考虑用 asyncio 异步处理取消和下单，这样能进一步缩短延迟。不过异步编程的复杂度会高一些，新手建议先用同步版本。

10.6 实战中的避坑指南

最后，我把自己踩过的坑总结一下，你写代码时注意避开：

  • 签名过期问题：Hyperliquid的签名有时效性，一般是5分钟。如果你构造订单后拖了很久才发送，签名会失效。我建议在发送前一刻才签名。
  • 订单ID重复：每个订单ID必须唯一。如果你用同一个ID发两次，第二次会被拒绝。我一般用 uuid.uuid4() 生成。
  • 网络超时：发送订单时设置超时参数，比如 timeout=5。别让程序无限等下去。
  • 取消未成交订单：只有状态为 "open" 的订单才能取消。已经成交或已取消的订单，再发取消会报错。
核心要点：签名是Hyperliquid安全机制的核心，无论下单还是取消，都必须签名。轮询是获取订单状态的唯一方式，别指望交易所主动通知你。修改订单就是取消+下单的组合操作，注意时延问题。
