第二十六课：数据存储与分析——SQLite + Pandas + 可视化

说实话，做量化交易这几年，我踩过最大的坑之一就是数据管理。

刚开始做 Hyperliquid 策略回测时，我习惯把每次拉到的订单簿数据直接扔进 CSV 文件。结果呢？三个月后，光一个交易对的 tick 数据就攒了十几个 GB，打开文件要等半分钟，查询某一天的记录更是噩梦。

后来我学乖了。用 SQLite 做本地存储，配合 Pandas 做分析，再画几张图看看趋势。这套组合拳打下来，数据管理再也没出过乱子。

今天我就把这套方法拆开揉碎了讲给你听。

为什么选 SQLite？

你可能想问：为什么不用 MySQL 或者 PostgreSQL？

我的回答很简单——本地量化研究不需要上服务器级数据库。

SQLite 有几个特点特别适合我们：

  • 零配置：不需要安装、不需要启动服务，一个文件就是一个数据库
  • 轻量级：整个库就几百 KB，Python 自带支持
  • 够用：单机读写性能足够应付百万级数据量

我在项目中遇到过最极端的情况——一个 SQLite 文件里存了 500 万条订单簿快照，查询某一天的记录仍然在 200 毫秒以内。嗯，够用了。

核心思路：把 Hyperliquid 的实时数据写入 SQLite，然后用 Pandas 读出来做分析，最后用 Matplotlib 或 Plotly 画图。

第一步：设计表结构

我个人习惯把不同数据类型分表存储。比如订单簿数据、成交数据、资金费率数据，各放一张表。

以订单簿为例，我通常这样设计：

CREATE TABLE orderbook_snapshots (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    symbol TEXT NOT NULL,
    timestamp INTEGER NOT NULL,
    bid_price_0 REAL,
    bid_size_0 REAL,
    ask_price_0 REAL,
    ask_size_0 REAL,
    bid_price_1 REAL,
    bid_size_1 REAL,
    ask_price_1 REAL,
    ask_size_1 REAL,
    -- 可以继续加更多档位
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_symbol_ts ON orderbook_snapshots(symbol, timestamp);

为什么要加索引？

我曾经试过不加索引直接查 100 万条数据，等了 8 秒才出结果。加上联合索引后，同样的查询 0.3 秒搞定。说白了，索引就是数据库的「目录」，没有目录你只能一页页翻书。

第二步：用 Python 写入数据

从 Hyperliquid 拿到数据后，写入 SQLite 其实就几行代码：

import sqlite3
import json
from hyperliquid import info

# 连接数据库（文件不存在会自动创建）
conn = sqlite3.connect('hyperliquid_data.db')
cursor = conn.cursor()

# 创建表（如果不存在）
cursor.execute('''
    CREATE TABLE IF NOT EXISTS orderbook_snapshots (
        id INTEGER PRIMARY KEY AUTOINCREMENT,
        symbol TEXT,
        timestamp INTEGER,
        bid_price REAL,
        bid_size REAL,
        ask_price REAL,
        ask_size REAL
    )
''')

# 获取 Hyperliquid 订单簿数据
info_client = info.Info()
data = info_client.l2_snapshot("BTC")

# 解析并写入
timestamp = int(time.time() * 1000)
for level in data['levels']:
    if level['side'] == 'B':
        bid_price = float(level['px'])
        bid_size = float(level['sz'])
    else:
        ask_price = float(level['px'])
        ask_size = float(level['sz'])

cursor.execute('''
    INSERT INTO orderbook_snapshots 
    (symbol, timestamp, bid_price, bid_size, ask_price, ask_size)
    VALUES (?, ?, ?, ?, ?, ?)
''', ('BTC', timestamp, bid_price, bid_size, ask_price, ask_size))

conn.commit()
conn.close()
小技巧：批量写入时用 executemany 代替逐条 execute，速度能提升 10 倍以上。我一般攒够 1000 条再一次性 commit。

第三步：用 Pandas 读取和分析

数据存进去了，怎么分析？Pandas 就是干这个的。

import pandas as pd
import sqlite3

conn = sqlite3.connect('hyperliquid_data.db')

# 直接读成 DataFrame
df = pd.read_sql_query('''
    SELECT * FROM orderbook_snapshots 
    WHERE symbol = 'BTC' 
    AND timestamp >= 1700000000000
    ORDER BY timestamp
''', conn)

conn.close()

# 计算买卖价差
df['spread'] = df['ask_price'] - df['bid_price']

# 计算中间价
df['mid_price'] = (df['bid_price'] + df['ask_price']) / 2

# 查看基本统计
print(df[['mid_price', 'spread']].describe())

你看，从数据库到 DataFrame 就是一行 read_sql_query 的事。Pandas 会自动把 SQL 查询结果转成表格，后面你想怎么算都行。

我个人最常用的几个分析场景：

  • 价差分析：计算买卖价差的均值、标准差，判断市场流动性
  • 价格波动率：用 df['mid_price'].pct_change().rolling(20).std() 算滚动波动率
  • 订单簿深度：统计不同价格档位的挂单量总和

第四步：可视化——让数据说话

数字看多了容易眼花。画成图，趋势一目了然。

import matplotlib.pyplot as plt
import matplotlib.dates as mdates

# 把时间戳转成可读格式
df['datetime'] = pd.to_datetime(df['timestamp'], unit='ms')

# 画图
fig, (ax1, ax2) = plt.subplots(2, 1, figsize=(12, 8), sharex=True)

# 上图：价格走势
ax1.plot(df['datetime'], df['mid_price'], label='Mid Price', color='#2196F3', linewidth=1)
ax1.set_ylabel('Price (USD)')
ax1.legend()
ax1.grid(True, alpha=0.3)

# 下图：价差变化
ax2.plot(df['datetime'], df['spread'], label='Bid-Ask Spread', color='#FF5722', linewidth=1)
ax2.set_ylabel('Spread (USD)')
ax2.legend()
ax2.grid(True, alpha=0.3)

# 格式化 x 轴时间
ax2.xaxis.set_major_formatter(mdates.DateFormatter('%H:%M'))
plt.xlabel('Time')

plt.tight_layout()
plt.show()

画出来的图长什么样？我描述一下：上面是价格曲线，下面是价差曲线。你会发现，价格剧烈波动的时候，价差往往会突然拉大——这就是流动性不足的信号。

注意：如果数据量很大（比如超过 10 万条），直接用 Matplotlib 画线图会非常慢。我的做法是先做降采样，比如每 10 秒取一个平均值，再画图。

避坑指南

做数据存储和分析，有几个坑我当年都踩过，分享给你：

  • 不要频繁 commit：每条数据都 commit 一次，写入速度会慢到让你怀疑人生。攒一批再写。
  • 时间戳用整数：别存字符串格式的时间，查询和排序都慢。用毫秒级整数时间戳，又快又准。
  • 定期清理旧数据：SQLite 文件不会自动瘦身。我写了个定时任务，每周删除 30 天前的数据，再用 VACUUM 回收空间。
  • 画图前先采样：10 万条数据直接画线图，Matplotlib 会卡住。先 resample 再画。
我的习惯：每天收盘后跑一次数据分析脚本，自动生成当天的价差图、深度图、波动率图，存成 PNG 文件。复盘的时候翻一翻，比看数字直观多了。

好了，数据存储和分析的流程就是这样。从 Hyperliquid 拿到数据，存进 SQLite，用 Pandas 算指标，最后画图看趋势。这套流程我用了两年多，稳定可靠。

你可以在自己的机器上试试，先跑一天的数据，看看 BTC 的价差在什么时间区间最小——那通常就是流动性最好的交易窗口。
