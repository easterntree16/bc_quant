性能优化：连接池管理、请求并发控制、数据缓存策略

做量化交易，尤其是对接 Hyperliquid 这种高性能 DEX，性能就是命根子。我见过太多人，策略逻辑写得天花乱坠，结果一上实盘，卡在 API 请求上，眼睁睁看着行情溜走。

说白了，你的策略再牛，如果数据拿得慢、下单堵住了，一切都是白搭。今天我就把我在 Hyperliquid 生态里摸爬滚打总结出来的三板斧——连接池、并发控制、缓存策略，一次性讲透。

核心思想：减少等待、复用资源、避免重复劳动。

一、连接池管理：别让握手拖垮你

每次发起 HTTP 请求，都要经历 TCP 三次握手、TLS 加密协商。你想想看，一次握手几十毫秒，高频策略一秒要发几十次请求，光握手就占了大半时间。

我个人习惯，永远用 aiohttp 配合 TCPConnector 来管理连接池。连接池说白了就是提前建好一堆连接，用的时候直接拿，用完放回去，省去反复握手的开销。

import aiohttp
import asyncio

# 创建一个连接池，限制最大连接数
connector = aiohttp.TCPConnector(
    limit=20,          # 总连接数上限
    limit_per_host=10, # 每个主机的连接数上限
    ttl_dns_cache=300, # DNS 缓存时间，单位秒
    force_close=False  # 复用连接，别每次用完就关
)

async with aiohttp.ClientSession(connector=connector) as session:
    # 后续所有请求都复用这个 session
    async with session.get('https://api.hyperliquid.xyz/info') as resp:
        data = await resp.json()

我的经验：limit 别设太大。我在项目中遇到过，把 limit 设成 100，结果本地端口号被占满，反而报错。一般 20-30 就够用了。

二、请求并发控制：别把交易所打崩了

有了连接池，你就能疯狂发请求了吗？当然不是。Hyperliquid 有严格的速率限制（rate limit），你发太快，直接给你返回 429，甚至封 IP。

我建议用信号量（Semaphore）来控制并发数。这玩意儿就像一个门卫，一次只放行 N 个人进去，其他人排队等着。

import asyncio

class RateLimiter:
    def __init__(self, max_concurrent=5):
        self.semaphore = asyncio.Semaphore(max_concurrent)
        self.last_request_time = 0

    async def acquire(self):
        async with self.semaphore:
            # 控制请求间隔，防止触发限流
            now = asyncio.get_event_loop().time()
            wait_time = max(0, 0.1 - (now - self.last_request_time))
            if wait_time > 0:
                await asyncio.sleep(wait_time)
            self.last_request_time = now
            return

# 使用示例
limiter = RateLimiter(max_concurrent=5)

async def safe_request(url):
    await limiter.acquire()
    async with session.get(url) as resp:
        return await resp.json()

嗯，这里要注意：并发数不是越大越好。我曾经把并发数调到 20，结果本地 CPU 先撑不住了，因为 asyncio 的事件循环处理不过来。5-10 是个比较稳妥的范围。

避坑指南：我曾经遇到过，信号量只控制了并发，没控制频率。结果 5 个请求同时发出去，还是触发了限流。所以一定要加上时间间隔控制，双保险。

三、数据缓存策略：别重复拿一样的数据

做交易的人都知道，有些数据变化很慢。比如交易对的元信息、历史 K 线、甚至某些深度数据，几秒钟内基本不变。你每次都去请求，纯属浪费带宽和算力。

我常用的缓存策略分三层：

缓存层级 存储位置 适用数据 过期时间
L1：内存缓存 Python 字典 / lru_cache 交易对信息、账户余额 5-30 秒
L2：本地文件缓存 JSON / SQLite 历史 K 线、回测数据 1 小时 - 1 天
L3：分布式缓存 Redis 多进程共享的行情数据 自定义

对于 Hyperliquid 的 WebSocket 实时行情，我一般不用缓存，因为数据本身就是实时推送的。但对于 REST API 的查询接口，比如 /info，我会用 functools.lru_cache 做内存缓存。

from functools import lru_cache
import time

@lru_cache(maxsize=128)
def get_cached_metadata(asset: str):
    """获取交易对元信息，缓存 10 秒"""
    # 实际请求 Hyperliquid API
    data = fetch_metadata_from_api(asset)
    return data

# 手动控制缓存过期
def get_metadata_with_ttl(asset: str, ttl=10):
    cache_key = f"meta_{asset}"
    cached = cache.get(cache_key)
    if cached and time.time() - cached['time'] < ttl:
        return cached['data']
    data = fetch_metadata_from_api(asset)
    cache[cache_key] = {'data': data, 'time': time.time()}

我的习惯：对于账户余额这种敏感数据，缓存时间不要超过 5 秒。我见过有人缓存了 30 秒的余额，结果下单时余额不足，直接爆仓。嗯，血的教训。

四、整体架构图：这三板斧怎么配合

下面这张图，是我自己项目里用的架构。你一看就明白，连接池、并发控制、缓存是怎么串起来的。

你看，数据从策略层出发，先查缓存。如果缓存里有，直接返回，不走后面的流程。如果没命中，才经过并发控制、连接池，最终到达 Hyperliquid API。这样设计，90% 的重复请求都能在缓存层被拦截掉。

五、实战组合拳：一个完整的请求函数

最后，我把这三样东西揉在一起，给你一个可以直接用的函数模板。

import asyncio
import aiohttp
from functools import lru_cache
import time

class HyperliquidClient:
    def __init__(self, max_concurrent=5, pool_size=20):
        self.connector = aiohttp.TCPConnector(
            limit=pool_size,
            limit_per_host=pool_size // 2,
            ttl_dns_cache=300
        )
        self.session = None
        self.semaphore = asyncio.Semaphore(max_concurrent)
        self.last_req_time = 0
        self.cache = {}

    async def __aenter__(self):
        self.session = aiohttp.ClientSession(connector=self.connector)
        return self

    async def __aexit__(self, *args):
        await self.session.close()

    async def request(self, endpoint: str, cache_ttl: int = 0):
        # 1. 检查缓存
        if cache_ttl > 0:
            cached = self.cache.get(endpoint)
            if cached and time.time() - cached['time'] < cache_ttl:
                return cached['data']

        # 2. 并发控制
        async with self.semaphore:
            now = time.time()
            wait = max(0, 0.1 - (now - self.last_req_time))
            if wait > 0:
                await asyncio.sleep(wait)
            self.last_req_time = time.time()

            # 3. 通过连接池发送请求
            url = f"https://api.hyperliquid.xyz/{endpoint}"
            async with self.session.get(url) as resp:
                data = await resp.json()

        # 4. 写入缓存
        if cache_ttl > 0:
            self.cache[endpoint] = {'data': data, 'time': time.time()}

        return data

# 使用示例
async def main():
    async with HyperliquidClient(max_concurrent=5) as client:
        # 获取元信息，缓存 10 秒
        meta = await client.request("info", cache_ttl=10)
        print(meta)

asyncio.run(main())

最后提醒一句：缓存虽好，但别乱用。对于下单、撤单这种操作，永远不要缓存。我见过有人把下单结果缓存了，结果重复下单，仓位直接翻倍。嗯，那场面，相当刺激。

好了，这三板斧你拿回去用，性能至少提升一个数量级。记住，做量化交易，快就是一切。但快的前提是稳，连接池、并发控制、缓存，就是帮你又快又稳的三大法宝。
