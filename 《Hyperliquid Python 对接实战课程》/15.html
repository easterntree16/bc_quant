WebSocket 实战（三）：实时账户余额与持仓更新、资金费率推送

好，咱们继续深入 WebSocket。

前两章我们搞定了行情数据，现在该碰真正的核心了——账户资金。说白了，就是你的钱包和仓位。

我个人习惯把这类数据叫做「命根子数据」。为什么？因为行情看错了可以止损，但账户数据如果没实时跟上，轻则错过平仓时机，重则爆仓了还不知道。我在早期做高频交易时，就吃过这个亏——WebSocket 断连了 3 秒，持仓没更新，结果止损单没触发。嗯，从那以后我对账户推送的稳定性要求极高。

一、账户数据订阅的核心逻辑

Hyperliquid 的 WebSocket 账户推送，和行情推送有个本质区别：需要鉴权。

你想想看，谁都能订阅你的余额？那不乱套了。所以订阅账户数据时，必须带上签名。具体流程是：

  1. 用你的私钥对特定消息签名
  2. 把签名结果作为订阅参数发送
  3. 服务端验证通过后，才开始推送你的账户数据

这里有个坑：签名有效期。我曾经遇到过签名过期导致推送中断的情况，排查了半天才发现是时间戳偏差。所以建议每次订阅前都重新生成签名，别复用旧的。

二、订阅账户余额与持仓更新

先看订阅消息的格式。我个人习惯把这类消息封装成一个函数，方便复用：

import time
import hashlib
import hmac
from eth_account.messages import encode_defunct
from web3 import Web3

def build_account_subscription(wallet_address, private_key):
    """
    构建账户订阅消息
    """
    # 时间戳，注意要用毫秒
    timestamp = int(time.time() * 1000)
    
    # 构造待签名的消息
    message = {
        "type": "subscribe",
        "channel": "account",
        "user": wallet_address,
        "timestamp": timestamp
    }
    
    # 签名过程
    message_str = str(message)
    message_hash = encode_defunct(text=message_str)
    signed_message = Web3().eth.account.sign_message(
        message_hash, 
        private_key=private_key
    )
    
    # 最终发送的订阅消息
    subscription = {
        "type": "subscribe",
        "channel": "account",
        "user": wallet_address,
        "signature": signed_message.signature.hex(),
        "timestamp": timestamp
    }
    
    return subscription

发送之后，服务端会返回确认消息。如果签名不对，会直接断开连接。嗯，这里要注意：签名用的私钥必须和钱包地址匹配，别搞混了测试网和主网的密钥。

三、解析账户推送数据

一旦订阅成功，你会收到类似这样的数据：

{
    "channel": "account",
    "data": {
        "user": "0x1234...",
        "balances": [
            {
                "coin": "USDC",
                "total": "10000.0",
                "hold": "2000.0",
                "withdrawable": "8000.0"
            },
            {
                "coin": "BTC",
                "total": "0.5",
                "hold": "0.2",
                "withdrawable": "0.3"
            }
        ],
        "positions": [
            {
                "coin": "BTC",
                "size": "1.0",
                "entryPx": "50000.0",
                "positionValue": "50000.0",
                "unrealizedPnl": "1000.0",
                "liquidationPx": "45000.0"
            }
        ],
        "time": 1699000000000
    }
}

字段说明：

字段 含义 注意点
total 总余额 包含冻结部分
hold 冻结余额 挂单占用的资金
withdrawable 可提现余额 total - hold
size 持仓数量 正数为多，负数为空
entryPx 开仓均价 加权平均计算
unrealizedPnl 未实现盈亏 按标记价格计算
liquidationPx 清算价格 接近时要警惕

我在项目中遇到过一个问题：持仓数据更新频率比余额高。因为行情波动时，未实现盈亏一直在变，但余额只有成交时才变。所以写代码时，建议把余额和持仓分开处理，别混在一起。

四、资金费率推送

资金费率是永续合约特有的机制。说白了，就是多头和空头之间定期结算的费用。Hyperliquid 的资金费率推送频率是 每小时一次，但实际结算可能更频繁。

订阅资金费率的消息比较简单，不需要签名：

{
    "type": "subscribe",
    "channel": "funding",
    "coin": "BTC"
}

返回的数据格式：

{
    "channel": "funding",
    "data": {
        "coin": "BTC",
        "fundingRate": "0.0001",
        "fundingTime": 1699000000000,
        "premium": "0.0002"
    }
}

这里有个关键点：fundingRate 是正值还是负值。正值表示多头付钱给空头，负值相反。我建议在策略中加一个判断：如果资金费率绝对值超过 0.1%，就要警惕了，说明市场情绪极度一边倒。

核心要点：

  • 账户订阅必须签名，且签名有时效性
  • 余额和持仓分开处理，更新频率不同
  • 资金费率每小时推送一次，但结算可能更频繁
  • 资金费率绝对值 > 0.1% 时需警惕

五、实战：构建实时账户监控器

咱们写一个简单的监控器，把账户数据和资金费率整合在一起：

import asyncio
import websockets
import json

class AccountMonitor:
    def __init__(self, wallet, private_key):
        self.wallet = wallet
        self.private_key = private_key
        self.balances = {}
        self.positions = {}
        self.funding_rates = {}
        
    async def connect(self):
        uri = "wss://api.hyperliquid.xyz/ws"
        async with websockets.connect(uri) as ws:
            # 订阅账户
            sub = build_account_subscription(self.wallet, self.private_key)
            await ws.send(json.dumps(sub))
            
            # 订阅资金费率
            funding_sub = {
                "type": "subscribe",
                "channel": "funding",
                "coin": "BTC"
            }
            await ws.send(json.dumps(funding_sub))
            
            # 持续接收
            async for message in ws:
                data = json.loads(message)
                self._handle_message(data)
                
    def _handle_message(self, data):
        channel = data.get("channel")
        if channel == "account":
            self._update_account(data["data"])
        elif channel == "funding":
            self._update_funding(data["data"])
            
    def _update_account(self, data):
        # 更新余额
        for bal in data["balances"]:
            self.balances[bal["coin"]] = bal
            
        # 更新持仓
        for pos in data["positions"]:
            self.positions[pos["coin"]] = pos
            
        # 检查清算风险
        for coin, pos in self.positions.items():
            if pos["liquidationPx"]:
                # 这里可以加报警逻辑
                pass
                
    def _update_funding(self, data):
        coin = data["coin"]
        rate = float(data["fundingRate"])
        self.funding_rates[coin] = rate
        
        # 资金费率过高时报警
        if abs(rate) > 0.001:
            print(f"⚠️ {coin} 资金费率异常: {rate}")

这段代码虽然简单，但已经能覆盖大部分场景了。我个人习惯在 _update_account 里加一个缓存机制——如果 5 秒内没收到更新，就主动重连。因为 WebSocket 偶尔会静默断开，你不主动检查根本不知道。

小技巧： 资金费率推送的 premium 字段可以帮你判断当前市场是升水还是贴水。如果 premium 持续为正，说明多头强势，资金费率大概率也会转正。

六、避坑指南

最后分享几个我踩过的坑：

  • 签名过期问题：我曾经用了一个旧的签名，结果订阅后 10 分钟就断连了。后来改成每次订阅前重新生成签名，问题解决。
  • 持仓数据延迟：有一次我发现持仓更新比实际成交慢了 2 秒，排查后发现是本地时间戳和服务端不一致。建议用服务端返回的 time 字段校准。
  • 资金费率推送丢失：如果网络波动，可能会漏掉某次推送。建议每小时主动拉一次资金费率做校验。

重要提醒： 账户数据涉及资金安全，绝对不要在日志中打印私钥或签名原文。我曾经见过有人把签名打印到控制台，结果被截屏泄露了。建议使用环境变量管理密钥。
