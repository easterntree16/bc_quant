实战策略（三）：套利策略——跨期套利、资金费率套利

套利策略，说白了就是「吃差价」。

我入行那会儿，有个老交易员跟我说过一句话，我一直记着：「市场永远在犯错，你要做的，就是找到那个错误。」套利就是干这个的。

在 Hyperliquid 上，套利的机会其实不少。今天咱们重点聊两种：跨期套利和资金费率套利。这两种策略，我个人觉得是新手最容易上手、风险也相对可控的。

一、跨期套利：吃时间差的饭

什么叫跨期套利？

同一个币，不同到期日的合约，价格不一样。比如 BTC 当周合约和次周合约，正常情况下它们应该有个合理的价差。但当市场情绪波动时，这个价差会拉大。我们就在价差拉大时进场，等它回归时平仓。

核心逻辑： 同一标的，不同到期日合约之间的价差，最终会回归合理区间。

1. 价差的计算

假设 BTC 当周合约价格是 60000 USDC，次周合约是 60500 USDC。

价差 = 次周价格 - 当周价格 = 500 USDC。

如果历史均值是 200 USDC，那现在明显偏高了。我们就可以做空次周、做多当周，等价差缩回去。

2. 代码实现

嗯，这里我直接给一个简化版的监控脚本。你在 Hyperliquid 上跑起来就能用。

import asyncio
import aiohttp
from typing import Tuple

class CrossMonthArbitrage:
    def __init__(self):
        self.base_url = "https://api.hyperliquid.xyz/info"
        self.symbol = "BTC"
        
    async def fetch_prices(self) -> Tuple[float, float]:
        """获取当周和次周合约价格"""
        async with aiohttp.ClientSession() as session:
            # 这里简化了，实际需要解析合约列表
            payload = {"type": "allMids"}
            async with session.post(self.base_url, json=payload) as resp:
                data = await resp.json()
                # 假设当周合约 key 是 "BTC-27SEP24"，次周是 "BTC-4OCT24"
                current_week = float(data.get("BTC-27SEP24", 0))
                next_week = float(data.get("BTC-4OCT24", 0))
                return current_week, next_week
    
    def calculate_spread(self, current: float, next_week: float) -> float:
        """计算价差"""
        return next_week - current
    
    async def monitor(self, threshold: float = 50):
        """监控价差，超过阈值则提示"""
        print(f"开始监控 {self.symbol} 跨期价差...")
        while True:
            try:
                cur, nxt = await self.fetch_prices()
                spread = self.calculate_spread(cur, nxt)
                print(f"当周: {cur:.2f}, 次周: {nxt:.2f}, 价差: {spread:.2f}")
                
                if abs(spread) > threshold:
                    print(f"⚠️ 价差超过阈值 {threshold}，考虑开仓")
                    # 这里可以接入你的交易逻辑
                    
                await asyncio.sleep(5)  # 每5秒检查一次
            except Exception as e:
                print(f"监控出错: {e}")
                await asyncio.sleep(10)

# 运行
async def main():
    arb = CrossMonthArbitrage()
    await arb.monitor(threshold=50)

asyncio.run(main())
我的经验： 阈值别设太死。我刚开始设了 30 USDC，结果一天触发几十次，全是噪音。后来改成 100 USDC，清净多了，收益反而更稳。

3. 注意事项

  • 流动性问题： 远月合约流动性差，滑点大。我建议只做当周和次周，别碰季度合约。
  • 资金费率影响： 跨期套利持仓过夜，两边都要付资金费率。如果费率方向不一致，可能吃掉利润。
  • 交割日效应： 临近交割，价差会剧烈波动。我一般提前一天平仓，不赌最后时刻。
避坑指南： 我曾经在交割日当天做跨期套利，结果价差瞬间拉大到 3 倍，两边都亏。后来我学乖了，交割日前 6 小时清掉所有仓位。

二、资金费率套利：赚永续合约的「租金」

资金费率，是永续合约特有的机制。

说白了，就是多头和空头之间互相付钱。当市场看多情绪浓时，多头付钱给空头；看空情绪浓时，空头付钱给多头。这个费率每 8 小时结算一次。

资金费率套利，就是利用这个机制。当费率极高或极低时，我们反向开仓，吃费率回归的收益。

核心逻辑： 资金费率不会永远偏离，极端值一定会回归。我们吃的是回归过程中的费率收益。

1. 策略思路

  1. 监控某个币的永续合约资金费率。
  2. 当费率超过某个阈值（比如年化 50% 以上），开反向仓位。
  3. 持有到费率回归正常（比如年化 10% 以下），平仓。

举个例子：

ETH 永续合约当前资金费率是 0.1%（8小时），年化高达 1095%。这说明多头极度拥挤。我们开空单，每 8 小时收一次费率。等费率跌回 0.01%，平仓走人。

2. 代码实现

import asyncio
import aiohttp

class FundingRateArbitrage:
    def __init__(self):
        self.base_url = "https://api.hyperliquid.xyz/info"
        self.symbol = "ETH"
        self.position = None  # 记录当前持仓方向
        
    async def fetch_funding_rate(self) -> float:
        """获取当前资金费率"""
        async with aiohttp.ClientSession() as session:
            payload = {"type": "fundingHistory", "coin": self.symbol}
            async with session.post(self.base_url, json=payload) as resp:
                data = await resp.json()
                # 取最近一次费率
                if data:
                    latest = data[0]
                    return float(latest["fundingRate"])
                return 0.0
    
    def annualized_rate(self, rate_8h: float) -> float:
        """将8小时费率转为年化"""
        return rate_8h * 3 * 365  # 每天3次，一年365天
    
    async def monitor(self, open_threshold: float = 0.0005, close_threshold: float = 0.0001):
        """监控费率，开仓和平仓"""
        print(f"开始监控 {self.symbol} 资金费率...")
        while True:
            try:
                rate = await self.fetch_funding_rate()
                annual = self.annualized_rate(rate)
                print(f"当前8小时费率: {rate:.6f}, 年化: {annual:.2f}%")
                
                if self.position is None:
                    # 没有持仓，判断是否开仓
                    if rate > open_threshold:
                        print(f"⚠️ 费率过高 ({rate:.6f})，开空单吃费率")
                        # 这里执行开空单逻辑
                        self.position = "short"
                    elif rate < -open_threshold:
                        print(f"⚠️ 费率过低 ({rate:.6f})，开多单吃费率")
                        # 这里执行开多单逻辑
                        self.position = "long"
                else:
                    # 已有持仓，判断是否平仓
                    if abs(rate) < close_threshold:
                        print(f"✅ 费率回归正常 ({rate:.6f})，平仓")
                        # 这里执行平仓逻辑
                        self.position = None
                
                await asyncio.sleep(60)  # 每分钟检查一次
            except Exception as e:
                print(f"监控出错: {e}")
                await asyncio.sleep(60)

async def main():
    arb = FundingRateArbitrage()
    await arb.monitor(open_threshold=0.0005, close_threshold=0.0001)

asyncio.run(main())
我的习惯： 开仓阈值我一般设年化 80% 以上，平仓阈值设年化 20% 以下。太小的阈值容易被震荡出局。

3. 风险点

  • 方向性风险： 如果开空单后币价暴涨，费率收益可能覆盖不了亏损。我一般会搭配一个现货对冲，但那样资金占用就大了。
  • 费率突变： 极端行情下，费率可能瞬间翻倍。我遇到过 ETH 费率从 0.05% 跳到 0.2%，空单亏惨了。
  • 资金占用： 套利需要双倍保证金（开仓+对冲），收益率其实没那么高。
避坑指南： 我曾经在 BTC 费率 0.15% 时开了空单，结果第二天 BTC 暴涨 10%，费率虽然收了 3 次，但方向亏损远大于费率收益。后来我加了止损，费率套利也要设止损线。

三、两种策略的对比

维度 跨期套利 资金费率套利
核心收益来源 价差回归 费率收益
持仓周期 数小时到数天 数小时到数天
主要风险 流动性、交割日 方向性波动、费率突变
资金效率 中等（双边保证金） 中等（可单边）
适合人群 有一定经验的交易者 能接受一定方向风险的交易者

我个人更偏爱资金费率套利，因为逻辑更简单，监控起来也省心。但如果你资金量比较大，跨期套利可能更适合，毕竟容量更大。

五、写在最后

套利策略听起来高大上，其实核心就一句话：找到市场定价的错误，然后等它纠正。

我在 Hyperliquid 上跑这两种策略跑了快一年，最大的感受是：别贪。年化 30%-50% 已经很好了，别想着翻倍。一旦贪了，就容易扛单，一扛单就出事。
