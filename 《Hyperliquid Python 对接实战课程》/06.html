第六章 REST API 实战（一）：获取订单簿深度、获取 K 线数据、获取交易历史

好，咱们今天直接上手干活。REST API 这东西，说白了就是你和 Hyperliquid 服务器之间的一条「数据管道」。你发个请求过去，它把数据扔回来。就这么简单。

我个人习惯，刚开始接触一个新交易所的 API 时，先别急着写策略。先拿三个最基础的数据接口练练手：订单簿深度、K 线、交易历史。这三个搞明白了，后面什么下单、撤单、查持仓，都是换汤不换药。

核心知识点： 本章你将掌握如何用 Python 调用 Hyperliquid 的 REST 接口，并解析返回的 JSON 数据。这是所有量化交易的第一步。

6.1 准备工作：你的第一个请求

先别管什么深度、K 线，咱们先确认一件事：你的 Python 环境能不能和 Hyperliquid 说上话。

我建议你直接用 requests 库，轻量、简单。别一上来就上什么 aiohttp、websocket，那是后面的事。

import requests

# Hyperliquid 的 REST API 基础地址
BASE_URL = "https://api.hyperliquid.xyz"

# 测试一下能不能通
def test_connection():
    try:
        resp = requests.get(f"{BASE_URL}/info", timeout=5)
        print(f"状态码: {resp.status_code}")
        print(f"返回数据: {resp.json()[:200]}...")  # 只打印前200字符
    except Exception as e:
        print(f"连接失败: {e}")

test_connection()

嗯，这里要注意：/info 接口返回的是交易所的元信息，比如支持的币种、合约参数等。如果这个能通，说明你的网络没问题，API 地址也没写错。

小技巧： 我在项目中遇到过好几次，明明代码没问题，就是拿不到数据。最后发现是代理或者防火墙把请求拦了。建议你在公司或者家里都先跑一下这个测试脚本，排除网络问题。

6.2 获取订单簿深度（Order Book Depth）

订单簿深度，说白了就是「当前市场上，在什么价格有多少人想买、多少人想卖」。这是做市商和短线交易员最常看的数据。

Hyperliquid 的订单簿接口路径是：/info/l2Book。你需要传一个参数：coin，也就是币种名称。

def get_order_book(coin: str):
    url = f"{BASE_URL}/info/l2Book"
    params = {"coin": coin}
    
    resp = requests.get(url, params=params)
    data = resp.json()
    
    # 解析返回数据
    bids = data['levels'][0]  # 买单
    asks = data['levels'][1]  # 卖单
    
    print(f"=== {coin} 订单簿深度 ===")
    print(f"前5档买单:")
    for level in bids[:5]:
        print(f"  价格: {level['px']}, 数量: {level['sz']}")
    
    print(f"前5档卖单:")
    for level in asks[:5]:
        print(f"  价格: {level['px']}, 数量: {level['sz']}")

# 试试看
get_order_book("BTC")

返回的数据结构是这样的：

字段 含义 示例值
px 价格 "65000.0"
sz 数量（张数） "1.5"
n 该价位挂单笔数 3

避坑指南： 我曾经踩过一个坑——Hyperliquid 的订单簿数据里，价格和数量都是字符串，不是浮点数。如果你直接拿去做数学运算，Python 会报错。记得先转成 float：float(level['px'])。

6.3 获取 K 线数据（Candlestick Data）

K 线数据，也叫蜡烛图。每个 K 线代表一段时间内的开盘价、最高价、最低价、收盘价和成交量。这是技术分析的基础。

Hyperliquid 的 K 线接口是：/info/candles。你需要传三个参数：coin、interval（时间周期）、limit（返回条数）。

def get_candles(coin: str, interval: str = "1h", limit: int = 10):
    url = f"{BASE_URL}/info/candles"
    params = {
        "coin": coin,
        "interval": interval,
        "limit": limit
    }
    
    resp = requests.get(url, params=params)
    data = resp.json()
    
    print(f"=== {coin} {interval} K线数据（最近{limit}条）===")
    for candle in data:
        print(f"时间: {candle['t']}, 开: {candle['o']}, 高: {candle['h']}, "
              f"低: {candle['l']}, 收: {candle['c']}, 成交量: {candle['v']}")

# 试试看
get_candles("ETH", "15m", 5)

返回的每个 K 线对象包含这些字段：

字段 含义 示例值
t 时间戳（毫秒） 1696000000000
o 开盘价 "3200.5"
h 最高价 "3250.0"
l 最低价 "3180.2"
c 收盘价 "3220.8"
v 成交量 "150.3"

小技巧： 时间戳 t 是毫秒级的，如果你想转成人类可读的时间，用 Python 的 datetime 模块：from datetime import datetime; datetime.fromtimestamp(t/1000)。我刚开始做的时候忘了除以1000，结果时间对不上，排查了半天。

6.4 获取交易历史（Trade History）

交易历史，就是最近发生的每一笔成交记录。谁在什么价格买了多少，一目了然。这个数据对分析市场微观结构很有用。

接口路径是：/info/trades。参数只需要 coin。

def get_trades(coin: str, limit: int = 10):
    url = f"{BASE_URL}/info/trades"
    params = {"coin": coin}
    
    resp = requests.get(url, params=params)
    data = resp.json()
    
    print(f"=== {coin} 最近{limit}笔交易 ===")
    for trade in data[:limit]:
        print(f"时间: {trade['time']}, 价格: {trade['px']}, "
              f"数量: {trade['sz']}, 方向: {trade['side']}")

# 试试看
get_trades("BTC", 5)

交易历史的数据结构：

字段 含义 示例值
time 成交时间（毫秒） 1696000000000
px 成交价格 "65000.0"
sz 成交数量 "0.5"
side 吃单方向（Bid/Ask） "Bid"

避坑指南： 我曾经以为 side 字段的 "Bid" 和 "Ask" 是「买方主动」和「卖方主动」的意思。其实不是。Bid 表示这笔交易是由买单吃掉的（卖方挂单，买方主动吃），Ask 则相反。这个搞反了，你的交易策略分析就会出大问题。

6.5 知识体系总览

为了让你更直观地理解这三个接口的关系，我画了一张图：

这三个接口，说白了就是三个不同的视角看市场：订单簿告诉你「现在能买/卖到什么价格」，K 线告诉你「过去一段时间价格怎么走的」，交易历史告诉你「每一笔成交是怎么发生的」。三者结合，你才能对市场有个完整的认识。

6.6 实战小练习

光看不练假把式。我给你留个小任务：

  1. 写一个函数，同时获取 BTC 的订单簿、K 线、交易历史数据
  2. 把订单簿的买卖价差（卖一价 - 买一价）算出来
  3. 把最近10笔交易的平均价格算出来
  4. 对比一下：当前买一价和最近10笔交易的平均价，哪个更高？

这个练习做完了，你对这三个接口的理解就能上一个台阶。我在项目里就是这么带新人的，效果不错。

核心总结： 订单簿深度、K 线、交易历史，是 Hyperliquid REST API 最基础也最重要的三个数据接口。掌握它们，你就拿到了进入量化交易世界的第一把钥匙。
