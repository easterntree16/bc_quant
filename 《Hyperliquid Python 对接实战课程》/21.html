第二十一章：策略框架搭建（三）：多时间周期分析、资金管理、仓位管理

好，我们继续往下走。前两章我们把策略框架的骨架搭起来了，事件驱动引擎和信号生成器都有了。但说实话，光有这些还不够——你想想看，一个策略如果只看单一时间周期，很容易被市场噪音耍得团团转。我早期做回测时就吃过这个亏，15分钟线看着是个完美突破，结果切换到1小时线一看，好家伙，就是个震荡区间上沿。

所以这一章，我们来解决三个核心问题：多时间周期怎么协同分析？资金怎么分配？仓位怎么动态调整？这三个东西绑在一起，才是一个能上实盘的策略框架。

21.1 多时间周期分析：别只看一个屏幕

我个人习惯把时间周期分成三层：

  • 大周期（4H/日线）：定方向。趋势是多是空？震荡还是单边？
  • 中周期（1H/30min）：找节奏。入场时机、回调位置。
  • 小周期（5min/1min）：抠细节。精确入场点、止损设置。

这三层的关系，说白了就是「大周期定战略，中周期定战术，小周期定战斗」。我在Hyperliquid上跑的一个BTC趋势策略，就是靠这个三层结构活下来的——大周期看日线EMA144，中周期看1小时MACD金叉死叉，小周期用5分钟K线找突破确认。

核心原则：小周期的信号必须服从大周期的方向。大周期多头，小周期只做多；大周期空头，小周期只做空。别逆着大周期去抄底摸顶，那是送钱。

代码实现上，我们需要一个MultiTimeframeAnalyzer类，它能同时维护多个周期的K线数据，并在每个周期上独立计算指标。然后通过一个投票或加权机制，把多个周期的信号合并成一个最终决策。

class MultiTimeframeAnalyzer:
    """
    多时间周期分析器
    支持任意数量周期，每个周期独立计算信号
    """
    def __init__(self, timeframes: list, indicators: dict):
        self.timeframes = timeframes  # ['5m', '15m', '1h']
        self.indicators = indicators  # { '5m': ['ema', 'rsi'], '1h': ['ema'] }
        self.buffers = {tf: deque(maxlen=200) for tf in timeframes}
        self.signals = {tf: None for tf in timeframes}
    
    def update(self, tf: str, kline: dict):
        """更新某个周期的K线数据"""
        self.buffers[tf].append(kline)

            self.signals[tf] = self._calc_signal(tf)

21.2 资金管理：别一把梭哈

资金管理是很多新手最容易忽略的环节。你策略胜率再高，仓位管理不好，一次黑天鹅就归零。我在Hyperliquid上见过太多人，开单就是全仓，结果一个插针直接爆仓。

我个人推荐凯利公式的改良版。标准凯利公式是：

f* = (bp - q) / b

其中：
f* = 最优投资比例
b  = 赔率（盈亏比）
p  = 胜率
q  = 败率（1-p）

但实际交易中，胜率和赔率都是估计值，直接套用凯利容易过激。所以我一般用半凯利或者四分之一凯利：

class KellyMoneyManager:
    """
    基于凯利公式的资金管理器
    默认使用半凯利，降低风险
    """
    def __init__(self, initial_capital: float, kelly_fraction: float = 0.5):
        self.capital = initial_capital
        self.kelly_fraction = kelly_fraction  # 0.5 = 半凯利
        self.trade_history = []
    
    def estimate_win_rate(self, lookback: int = 50) -> float:
        """根据最近交易记录估算胜率"""
        recent = self.trade_history[-lookback:]
        if len(recent) == 0:
            return 0.5  # 默认50%
        wins = sum(1 for t in recent if t['pnl'] > 0)
        return wins / len(recent)
    
    def estimate_avg_win_loss_ratio(self, lookback: int = 50) -> float:
        """估算平均盈亏比"""
        recent = self.trade_history[-lookback:]
        if len(recent) == 0:
            return 1.5  # 默认1.5
        wins = [t['pnl'] for t in recent if t['pnl'] > 0]
        losses = [abs(t['pnl']) for t in recent if t['pnl'] <= 0]
        if len(losses) == 0:
            return 2.0
        avg_win = sum(wins) / len(wins) if wins else 0
        avg_loss = sum(losses) / len(losses) if losses else 1
        return avg_win / avg_loss if avg_loss > 0 else 1.5
    
    def calc_position_size(self, current_price: float) -> float:
        """计算本次开仓数量"""
        p = self.estimate_win_rate()
        b = self.estimate_avg_win_loss_ratio()
        q = 1 - p
        
        # 凯利公式
        kelly = (b * p - q) / b
        kelly = max(0, min(kelly, 0.25))  # 限制最大25%
        
        # 应用凯利分数
        fraction = kelly * self.kelly_fraction
        
        # 计算仓位价值
        position_value = self.capital * fraction
        
        # 返回合约数量
        return position_value / current_price

注意：凯利公式假设你的胜率和赔率是稳定的。但市场会变，所以一定要加一个「最大仓位限制」。我一般设总资金的20%为单笔最大仓位，不管凯利算出来多大，都不能超过这个数。

21.3 仓位管理：动态调整的艺术

仓位管理跟资金管理不一样。资金管理决定「每次开多少」，仓位管理决定「已经开仓了，怎么动态调整」。说白了，就是加仓、减仓、止损、止盈这一套。

我常用的仓位管理策略是金字塔加仓法：

  • 初始仓位：总资金的5%
  • 第一次加仓：价格朝有利方向移动一个ATR，加3%
  • 第二次加仓：再移动一个ATR，加2%
  • 第三次加仓：再移动一个ATR，加1%

为什么是递减？因为价格越往极端走，回调风险越大。你想想看，如果价格已经涨了3个ATR，你还重仓追，一个回调就把你打回原形。

class PyramidPositionManager:
    """
    金字塔仓位管理器
    支持动态加仓、减仓、移动止损
    """
    def __init__(self, atr_period: int = 14):
        self.atr_period = atr_period
        self.positions = []  # 记录每笔加仓
        self.current_atr = None
    
    def update_atr(self, klines: list):
        """更新ATR值"""
        if len(klines) < self.atr_period + 1:
            return
        highs = [k['high'] for k in klines[-self.atr_period:]]
        lows = [k['low'] for k in klines[-self.atr_period:]]
        closes = [k['close'] for k in klines[-self.atr_period:]]
        
        tr_values = []
        for i in range(1, len(closes)):
            tr = max(
                highs[i] - lows[i],
                abs(highs[i] - closes[i-1]),
                abs(lows[i] - closes[i-1])
            )
            tr_values.append(tr)
        
        self.current_atr = sum(tr_values) / len(tr_values)
    
    def should_add_position(self, entry_price: float, current_price: float, 
                           direction: int) -> bool:
        """
        判断是否应该加仓
        direction: 1=多头, -1=空头
        """
        if self.current_atr is None:
            return False
        
        # 计算价格移动了多少个ATR
        price_move = (current_price - entry_price) * direction
        atr_moves = price_move / self.current_atr
        
        # 当前加仓次数
        add_count = len(self.positions)
        
        # 每次加仓间隔1个ATR，最多加3次
        if atr_moves >= (add_count + 1) and add_count < 3:
            return True
        return False
    
    def calc_add_size(self, base_size: float, add_count: int) -> float:
        """计算本次加仓数量（递减）"""
        sizes = [base_size, base_size * 0.6, base_size * 0.4]
        if add_count < len(sizes):
            return sizes[add_count]
        return 0
    
    def calc_trailing_stop(self, current_price: float, direction: int) -> float:
        """计算移动止损价"""
        if self.current_atr is None:
            return None
        
        # 使用2倍ATR作为移动止损距离
        stop_distance = self.current_atr * 2
        
        if direction == 1:  # 多头
            return current_price - stop_distance
        else:  # 空头
            return current_price + stop_distance

关键点：移动止损不是一成不变的。我习惯在加仓后把止损往上提，保证整体仓位不亏损。比如第一次开仓后止损设在-1ATR，加仓后止损移到开仓价，再加仓后移到+0.5ATR。这样即使后面回调，最多也就是回吐部分利润，不会伤到本金。

21.4 三者如何协同工作

好，现在我们把多时间周期分析、资金管理、仓位管理串起来。整个流程是这样的：

  1. 多周期分析器给出当前市场状态（趋势/震荡）和方向信号
  2. 资金管理器根据历史交易数据，算出本次开仓的合理仓位大小
  3. 仓位管理器在开仓后动态跟踪，决定何时加仓、何时移动止损

一个小建议：刚开始实盘的时候，别急着上全自动。我建议你先用手动模式跑一周，把多周期信号、资金计算、仓位调整这些逻辑都手动验证一遍。等确认逻辑没问题了，再切换到自动执行。这一步能帮你省下不少学费。
