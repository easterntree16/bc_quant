第十一章：下单操作（三）：止损单、止盈单、追踪止损单的实现

止损单、止盈单、追踪止损单——这三个东西，说白了就是帮你「管住手」的工具。我见过太多人，明明策略跑得好好的，结果因为手动平仓慢了半拍，利润全吐回去。嗯，我自己早期也吃过这个亏。

今天我们就来聊聊，在 Hyperliquid 上怎么用 Python 实现这三种订单。别急，我会把每个细节都拆开讲清楚。

11.1 止损单（Stop Loss）

止损单的逻辑很简单：当价格触及某个不利位置时，自动平仓。但 Hyperliquid 的止损单，和我们传统交易所的有点不一样。

它其实是一个「条件触发 + 市价单」的组合。你设置一个触发价格，一旦市场价碰到它，系统就帮你发一个市价平仓单。

核心要点：止损单不是挂单，而是条件单。触发后立即以市价成交，不保证滑点。

来看代码实现：

import asyncio
from hyperliquid import HyperliquidClient

async def place_stop_loss(client, symbol, position_side, stop_price, size):
    """
    设置止损单
    :param client: Hyperliquid 客户端实例
    :param symbol: 交易对，如 "ETH-USD"
    :param position_side: 持仓方向，"LONG" 或 "SHORT"
    :param stop_price: 止损触发价格
    :param size: 止损数量（合约张数）
    """
    # 根据持仓方向决定触发条件
    if position_side == "LONG":
        # 多头：价格跌破止损价时触发
        trigger_condition = "lte"  # less than or equal
    else:
        # 空头：价格涨破止损价时触发
        trigger_condition = "gte"  # greater than or equal
    
    # 构建止损单参数
    order_params = {
        "symbol": symbol,
        "side": "SELL" if position_side == "LONG" else "BUY",
        "size": str(size),
        "order_type": {
            "trigger": {
                "trigger_price": str(stop_price),
                "trigger_condition": trigger_condition,
                "is_market": True  # 市价触发
            }
        },
        "reduce_only": True  # 只减仓，不开新仓
    }
    
    try:
        response = await client.place_order(**order_params)
        print(f"止损单已设置：触发价 {stop_price}")
        return response
    except Exception as e:
        print(f"止损单设置失败：{e}")
        return None

个人经验：我在项目中遇到过一个问题——止损单的 reduce_only 参数一定要设为 True。否则，如果你持仓不够，系统可能会给你开反向仓位，那可就麻烦了。

11.2 止盈单（Take Profit）

止盈单和止损单是「镜像关系」。一个保护本金，一个锁定利润。实现方式几乎一样，只是触发方向相反。

你想想看，做多的时候，止损设在下方，止盈设在上方。做空则反过来。这个逻辑很直观，但代码里要注意触发条件的设置。

async def place_take_profit(client, symbol, position_side, target_price, size):
    """
    设置止盈单
    """
    if position_side == "LONG":
        # 多头：价格涨到目标价时触发
        trigger_condition = "gte"
    else:
        # 空头：价格跌到目标价时触发
        trigger_condition = "lte"
    
    order_params = {
        "symbol": symbol,
        "side": "SELL" if position_side == "LONG" else "BUY",
        "size": str(size),
        "order_type": {
            "trigger": {
                "trigger_price": str(target_price),
                "trigger_condition": trigger_condition,
                "is_market": True
            }
        },
        "reduce_only": True
    }
    
    try:
        response = await client.place_order(**order_params)
        print(f"止盈单已设置：目标价 {target_price}")
        return response
    except Exception as e:
        print(f"止盈单设置失败：{e}")
        return None

注意：止盈单和止损单不要设置相同的触发价格。我曾经见过有人把止损止盈设在同一价位，结果两个单子互相打架，系统直接报错。

11.3 追踪止损单（Trailing Stop）

追踪止损单就更有意思了。它像一个「会移动的止损线」。价格往有利方向走，止损线就跟着移动；价格回调，止损线不动。

说白了，就是帮你「锁定利润的同时，给行情留点喘息空间」。

Hyperliquid 的追踪止损单，需要你设置两个参数：

  • 激活价格（activation price）： 价格达到这个位置，追踪才开始生效
  • 回调幅度（callback rate）： 从最高点回调多少百分比，触发止损

举个例子：你做多 ETH，当前价格 3000。你设置激活价 3100，回调幅度 2%。当价格涨到 3100 时，追踪开始。如果价格继续涨到 3200，止损线就上移到 3136（3200 - 2%）。如果价格从 3200 跌回 3136，止损触发。

async def place_trailing_stop(client, symbol, position_side, 
                              activation_price, callback_rate, size):
    """
    设置追踪止损单
    :param callback_rate: 回调幅度，如 0.02 表示 2%
    """
    order_params = {
        "symbol": symbol,
        "side": "SELL" if position_side == "LONG" else "BUY",
        "size": str(size),
        "order_type": {
            "trailing_stop": {
                "activation_price": str(activation_price),
                "callback_rate": str(callback_rate),
                "is_market": True
            }
        },
        "reduce_only": True
    }
    
    try:
        response = await client.place_order(**order_params)
        print(f"追踪止损已设置：激活价 {activation_price}，回调 {callback_rate*100}%")
        return response
    except Exception as e:
        print(f"追踪止损设置失败：{e}")
        return None

我的建议：回调幅度不要设得太小。比如 0.5% 这种，行情稍微一波动就触发了。我个人习惯用 1.5% - 3%，具体看品种的波动率。

11.4 三种订单的对比

为了方便你理解，我整理了一个表格：

订单类型 触发条件 适用场景 注意事项
止损单 价格触及固定价位 控制最大亏损 滑点可能较大
止盈单 价格触及固定价位 锁定目标利润 可能错过更大行情
追踪止损 价格从高点回调一定比例 趋势行情中保护利润 震荡行情容易频繁触发

11.5 实战中的组合策略

在实际交易中，我很少只用一种订单。通常的做法是：

  1. 开仓时：同时挂上止损单和止盈单
  2. 行情启动后：取消止盈单，换成追踪止损单
  3. 追踪止损触发后：如果还想做，重新评估再入场

这样做的好处是：开仓时风险可控，行情走起来后利润能最大化。

async def combined_strategy(client, symbol, position_side, 
                            entry_price, stop_loss, take_profit,
                            trailing_activation, callback_rate, size):
    """
    组合策略：先挂止损止盈，行情启动后切换为追踪止损
    """
    # 第一步：设置止损和止盈
    sl_task = place_stop_loss(client, symbol, position_side, stop_loss, size)
    tp_task = place_take_profit(client, symbol, position_side, take_profit, size)
    await asyncio.gather(sl_task, tp_task)
    
    # 第二步：监控价格，达到激活价后切换
    while True:
        current_price = await client.get_mark_price(symbol)
        
        if position_side == "LONG" and current_price >= trailing_activation:
            # 取消止盈单，设置追踪止损
            await client.cancel_all_orders(symbol)
            await place_trailing_stop(client, symbol, position_side, 
                                      trailing_activation, callback_rate, size)
            print("已切换为追踪止损模式")
            break
            
        elif position_side == "SHORT" and current_price <= trailing_activation:
            await client.cancel_all_orders(symbol)
            await place_trailing_stop(client, symbol, position_side,
                                      trailing_activation, callback_rate, size)
            print("已切换为追踪止损模式")
            break
        
        await asyncio.sleep(1)  # 每秒检查一次

避坑指南：我曾经在切换订单时忘记取消旧的止盈单，结果追踪止损和止盈单同时生效，仓位被平了两次。嗯，从那以后我每次切换前都会先 cancel_all_orders。
