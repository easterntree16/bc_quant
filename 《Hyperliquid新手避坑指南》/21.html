第二十一节：API安全——IP白名单、密钥轮换、避免明文存储

API密钥这东西，说白了就是你的资金通行证。

我见过太多人把API密钥直接写在代码里，然后上传到GitHub。结果呢？几分钟内机器人就把账户里的钱搬空了。嗯，这不是段子，是我亲眼见过的真实案例。

今天咱们就聊聊，怎么把API密钥这玩意儿管好。

一、IP白名单：给API加把物理锁

IP白名单是什么？简单说，就是只允许特定IP地址访问你的API。

我个人习惯，哪怕只是测试用的API，也一定会绑IP。为什么？因为多一层防护总比没有强。

核心原则：只允许你的交易服务器IP访问API，其他IP一律拒绝。

在Hyperliquid上设置IP白名单，流程大概是这样的：

  1. 登录你的交易服务器，查一下公网IP（用 curl ifconfig.me 就能看到）
  2. 在Hyperliquid的API管理页面，添加这个IP到白名单
  3. 保存后，测试一下——换个IP试试能不能访问，应该被拒绝

注意：如果你用的是云服务器，IP可能会变。建议用弹性公网IP，或者定期检查白名单。

我曾经遇到过一个用户，他把API绑了家里的IP，结果出差时想交易，发现API全挂了。嗯，这就是没考虑动态IP的后果。

二、密钥轮换：别让密钥活太久

密钥轮换，说白了就是定期换密码。

你想想看，如果你的密钥泄露了，但你没发现，那对方就能一直用你的API做交易。密钥轮换的目的，就是把这种风险控制在有限时间内。

我个人建议的轮换周期：

使用场景 建议轮换周期 说明
高频交易机器人 每周一次 交易量大，风险高
普通交易 每月一次 中等风险
只读API 每季度一次 风险较低，但也要换

怎么实现自动轮换？我写了个小脚本，大家可以参考：

#!/bin/bash
# 密钥轮换脚本 - 每月执行一次

# 生成新密钥对
NEW_KEY=$(openssl rand -hex 32)

# 更新Hyperliquid API密钥
curl -X POST https://api.hyperliquid.xyz/info \
  -H "Content-Type: application/json" \
  -d '{"type": "rotateKey", "newKey": "'$NEW_KEY'"}'

# 更新本地配置文件
sed -i "s/API_KEY=.*/API_KEY=$NEW_KEY/" /etc/trading-bot.conf

# 记录日志
echo "$(date) - 密钥已轮换" >> /var/log/key-rotation.log

小技巧：可以用cron定时任务来跑这个脚本。比如每月1号凌晨3点执行一次。

三、避免明文存储：密钥不是便利贴

明文存储密钥，就像把银行卡密码写在便利贴上贴在电脑屏幕前。太危险了。

我见过最离谱的案例：有人把API密钥写在Python脚本里，然后脚本上传到了GitHub公开仓库。结果不到10分钟，账户里的USDC全被转走了。

正确的做法是什么？

  • 环境变量：把密钥存在环境变量里，代码里用 os.getenv() 读取
  • 密钥管理服务：比如AWS Secrets Manager、HashiCorp Vault
  • 加密配置文件：用GPG或openssl加密配置文件，运行时解密

举个例子，用环境变量的方式：

# 在.bashrc或.zshrc里设置
export HYPERLIQUID_API_KEY="your-api-key-here"
export HYPERLIQUID_SECRET="your-secret-here"

# Python代码里读取
import os
api_key = os.getenv("HYPERLIQUID_API_KEY")
secret = os.getenv("HYPERLIQUID_SECRET")

千万别做这些事：

  • 不要把密钥写在代码里
  • 不要把密钥上传到GitHub
  • 不要把密钥放在日志文件里
  • 不要在聊天工具里发密钥

我曾经...把API密钥写在一个测试脚本里，然后忘了删。结果那个脚本被同事上传到了内部GitLab。虽然没泄露到外网，但内部人员也能看到。从那以后，我所有脚本里都只用环境变量。

还有一次，我帮一个朋友排查问题，发现他的API密钥居然写在了一个文本文件里，文件名就叫"密钥.txt"。嗯，这跟把密码写在便利贴上贴电脑上有什么区别？

记住一句话：密钥的安全，就是资金的安全。别嫌麻烦，该做的防护一个都不能少。

最后的小建议：每周花5分钟检查一下你的API密钥状态。看看有没有异常访问记录，密钥有没有过期。这5分钟，可能帮你省下几万U。
