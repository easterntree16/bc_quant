27、常见错误代码：错误码解读（如-2011、-1013）、处理流程

做Hyperliquid交易，最烦人的就是突然弹出一个错误码。我刚开始接触时，看到-2011、-1013这些数字，第一反应是「完了，是不是账户出问题了？」后来踩的坑多了，才发现大部分错误码其实都是「纸老虎」——只要知道它想说什么，处理起来很简单。

今天我就把Hyperliquid上最常见的几个错误码，连同我自己的处理经验，一次性讲清楚。你想想看，与其等出错了再手忙脚乱，不如提前把这些「暗号」背下来。

错误码速查表

先给一张总表，方便你以后直接查。我把它按严重程度分了类：

错误码 含义 严重程度 常见场景
-2011 订单被拒绝（价格/数量违规） 中 限价单价格超出范围
-1013 交易对不存在或已下架 低 输入了错误的币种名称
-2010 余额不足 高 保证金不够开仓
-2012 订单数量超过限制 中 单笔下单量过大
-1001 内部系统错误 高 网络波动或服务器异常
-2015 API密钥权限不足 高 只读密钥尝试交易

错误码详解：-2011

-2011 是我个人遇到最多的错误码。说白了，就是交易所告诉你：「你这个订单我不接。」

为什么会这样？通常有几种情况：

  • 价格超出范围：比如当前市价是100 USDC，你挂了一个50 USDC的买单。Hyperliquid有价格保护机制，太离谱的价格会被直接拒绝。
  • 数量精度不对：Hyperliquid对每个币种都有最小交易单位和精度要求。比如BTC只能精确到0.001，你填了0.0001就会报错。
  • 订单类型不支持：某些特殊订单（如IOC、FOK）在特定市场可能被禁用。

我的处理流程：

  1. 先检查订单价格是否在合理范围内（一般不超过当前市价的±20%）
  2. 再确认数量精度——去Hyperliquid的「市场信息」接口查一下最小交易单位
  3. 如果还不行，换个订单类型试试（比如把限价单改成市价单）

小技巧： 我在写交易机器人时，习惯在每次下单前先调用一次 get_exchange_info() 接口，把当前市场的价格范围、精度限制都拉下来。这样能提前过滤掉99%的-2011错误。

错误码详解：-1013

-1013 这个错误码，说白了就是「你找的币不存在」。听起来很蠢对吧？但我曾经就犯过这种低级错误——把「ETH」写成了「ETC」，结果卡了半天。

常见原因：

  • 币种名称拼写错误（大小写敏感）
  • 交易对格式不对（比如应该用「ETH-USDC」而不是「ETHUSDC」）
  • 该币种在Hyperliquid上确实没有上架

注意： Hyperliquid上的交易对命名规则是「基础币种-计价币种」，比如 BTC-USDC、ETH-USDC。不要用其他交易所的命名习惯来套。

我的处理方式很简单：直接去Hyperliquid官网的「Markets」页面看一眼，或者用API拉一下 get_all_markets() 列表。嗯，这一步花不了10秒钟，但能省下你半小时的排查时间。

错误码详解：-2010 和 -2012

这两个错误码其实是一对「兄弟」——一个管钱，一个管量。

-2010（余额不足）：这个不用多解释，就是你的账户里钱不够。但要注意，Hyperliquid的保证金计算方式跟其他交易所不太一样。它用的是「全仓模式」，所以你的可用余额 = 总资产 - 所有持仓的维持保证金。有时候你看着账户里有钱，但实际可用余额可能是负数——因为持仓占用了保证金。

-2012（数量超限）：每个交易所有单笔最大下单量的限制。Hyperliquid上，BTC的单笔最大订单量是100 BTC（具体数值会动态调整）。如果你是个大户，想一把梭哈，就得拆成多笔订单。

我的建议： 写代码时，最好在每次下单前先检查一下 get_account_balance() 和 get_market_limits()。别等到报错了再回头改，那样容易错过行情。

我的通用处理流程

不管遇到什么错误码，我个人的处理流程都是固定的。你直接照搬就行：

  1. 先别慌，记录错误码和上下文——包括时间、订单参数、当前市场状态。这些信息后面排查时非常有用。
  2. 查速查表——如果是-2011、-1013这种常见错误，直接按表里的建议处理。
  3. 检查网络状态——有时候错误码是网络波动导致的假象。我习惯先ping一下Hyperliquid的API端点，确认网络没问题。
  4. 重试一次——对于-1001这种系统错误，等3-5秒重试一次。如果连续3次都失败，就停下来。
  5. 记录日志——把错误信息写到日志文件里，方便后续复盘。我一般会记录：错误码、时间、订单参数、重试次数。

避坑指南： 我曾经犯过一个错误——在收到-2011错误后，没有检查原因就直接重试。结果连续下了10次单，全部被拒绝，还白白浪费了API调用次数。记住：先排查原因，再决定是否重试。

代码示例：错误处理模板

下面是我写交易机器人时用的错误处理模板。你可以直接复制过去用：

def place_order_with_retry(symbol, side, price, quantity, max_retries=3):
    for attempt in range(max_retries):
        try:
            result = hyperliquid_api.place_order(
                symbol=symbol,
                side=side,
                price=price,
                quantity=quantity
            )
            return result
            
        except HyperliquidError as e:
            error_code = e.code
            
            # 常见错误直接处理
            if error_code == -2011:
                # 检查价格和数量
                print(f"订单被拒绝，检查价格和数量: {e}")
                break  # 不重试，先排查
                
            elif error_code == -1013:
                print(f"交易对不存在: {symbol}")
                break
                
            elif error_code == -2010:
                print("余额不足，停止下单")
                break
                
            elif error_code == -1001:
                # 系统错误，可以重试
                if attempt < max_retries - 1:
                    time.sleep(3)
                    continue
                else:
                    print("系统错误，重试次数用尽")
                    
            else:
                # 未知错误，记录日志
                log_error(error_code, e)
                break
                
    return None

这段代码的核心思路是：对已知错误直接处理，对系统错误才重试。别傻乎乎地什么错误都重试，那样只会让情况更糟。

最后说两句

错误码这东西，说白了就是交易所跟你沟通的语言。你读懂了，它就是个提示；读不懂，它就是拦路虎。我个人建议你把上面那张速查表截图保存，或者打印出来贴在工位上。遇到错误码时，先查表，再动手。

嗯，关于错误码的解读就讲到这里。记住：大部分错误码都不是你的错，而是参数没调对。冷静下来，按流程走一遍，问题基本都能解决。
