01

TypeScript 入门与环境搭建

准备篇约 2 小时前置：JavaScript 基础

学习目标

  • 理解 TypeScript 是什么、为什么需要它、它是怎么工作的
  • 从零搭建开发环境，编译并运行第一个 TS 程序
  • 认识 tsconfig.json，掌握最常用的编译配置

1.1 什么是 TypeScript

TypeScript（简称 TS）是由微软在 2012 年发布的开源编程语言，主导者是 C# 之父 Anders Hejlsberg。它只有一个核心目标：给 JavaScript 加上类型系统。

最准确的一句话定义：TypeScript 是 JavaScript 的超集。意思是——任何一段合法的 JavaScript 代码，本身就是合法的 TypeScript 代码。你可以在 .ts 文件里只写纯 JS，编译器也能正常通过。TS 是在 JS 之上「增量叠加」的能力，而不是一门全新的语言。

🧠 基本原理：TS 是怎么工作的

你写的 .ts 文件不会直接被浏览器或 Node 运行。它要经过一个叫 tsc（TypeScript Compiler，TS 官方编译器）的程序处理，分两步：

  1. 类型检查：读完全部代码，根据你写的类型标注做静态分析，发现类型不匹配就报错（但不会中断生成）。
  2. 转译：把类型标注「擦除」掉，生成一份干净的 JavaScript 文件（.js）。
// 你写的 .ts 文件
function add(a: number, b: number): number {
  return a + b;
}

// tsc 编译后生成的 .js 文件（类型全部被擦除）
function add(a, b) {
  return a + b;
}

关键结论：类型只存在于编译期，运行时根本不存在。所以 TS 不会让程序变慢（零运行时开销），类型系统纯粹是开发阶段的「护栏」。

1.2 为什么需要 TypeScript（应用场景）

🎯 应用场景
  • 大型前端项目：React / Vue 官方脚手架默认支持 TS。项目上百个文件时，JS 的「自由」会变成灾难——改一个函数签名，调用它的地方全崩，还得靠人肉找。
  • Node.js 后端：NestJS、Fastify 等主流框架直接以 TS 为一等公民。
  • 开源库 / npm 包：给库加上类型声明，用户写代码时就能获得智能提示。
  • 团队协作：类型就是「接口契约」——别人定义的函数，你不用看实现就知道怎么调用；重构时有编译器兜底。
  • 长期维护：半年后回看自己的代码，类型标注是最好的文档。
🧠 一个直观对比：同样的 bug，JS 和 TS 的区别
// 纯 JavaScript：错误要等运行时才暴露
function getPrice(item) {
  return item.price * item.count;
}
getPrice({ price: "9.9", count: 3 });  // 结果 "9.99.9" 字符串拼接，没人发现

// TypeScript：写代码的当下就报错
function getPrice(item: { price: number; count: number }): number {
  return item.price * item.count;
}
getPrice({ price: "9.9", count: 3 });  // ❌ 类型 "string" 不能赋值给类型 "number"

1.3 实操：搭建开发环境（保姆级步骤）

⚙️ 操作步骤（Windows / macOS 通用）
  1. 安装 Node.js：打开 nodejs.org，下载 LTS 版本（18 或更高），一路默认安装。装完打开终端（Windows 用 PowerShell，macOS 用终端），输入 node -v 和 npm -v，能打印版本号即成功。
  2. 安装 TypeScript：终端执行 npm install -g typescript（全局安装）。验证：tsc -v，能看到类似 Version 5.x.x。
  3. 安装编辑器：推荐 VSCode（code.visualstudio.com）。TS 的语法提示、跳转、自动补全由官方插件内置，无需额外安装；可选装扩展：Prettier（格式化）、Error Lens（错误行内显示）。
  4. 创建项目目录：终端执行：
mkdir my-ts-learn
cd my-ts-learn
npm init -y        # 生成 package.json
  1. 写第一个程序：新建文件 hello.ts，粘贴下面的代码。
// hello.ts —— 你的第一个 TypeScript 程序
const message: string = "Hello, TypeScript!";
const year: number = 2026;
console.log(`${message} 今年是 ${year} 年。`);
  1. 编译并运行：
tsc hello.ts      # 编译，生成 hello.js
node hello.js     # 运行，输出：Hello, TypeScript! 今年是 2026 年。
  1. 试试类型检查：把 const year: number = 2026 改成 const year: number = "2026"，再执行 tsc hello.ts，会看到红色报错：Type 'string' is not assignable to type 'number' —— 这就是 TS 在保护你。
  2. （推荐）直接运行 .ts：每次编译再运行太麻烦，安装 tsx 可以直接跑 TS 文件：npm install -D tsx，然后 npx tsx hello.ts。教程后续示例都建议用这种方式。
  3. 生成配置文件：执行 tsc --init，会生成 tsconfig.json，这是 TS 项目的「总开关」，第 9 章会详解。现在只需知道它存在即可。

1.4 实际案例：一个带类型的温度转换工具

💻 案例：把 C 语言风格的「无类型思维」切换过来
// temp.ts —— 温度转换工具
// ① 函数参数和返回值都标了类型：参数只能是数字，返回的一定是数字
function celsiusToFahrenheit(c: number): number {
  return (c * 9) / 5 + 32;
}

function fahrenheitToCelsius(f: number): number {
  return ((f - 32) * 5) / 9;
}

// ② 变量类型由初始值自动推断（不需要写，TS 自己会算）
const t1 = celsiusToFahrenheit(25);   // t1 被推断为 number
const t2 = fahrenheitToCelsius(77);   // t2 被推断为 number

console.log(`25°C = ${t1.toFixed(1)}°F`);   // 25°C = 77.0°F
console.log(`77°F = ${t2.toFixed(1)}°C`);   // 77°F = 25.0°C

// ③ 故意传错类型，编译器立刻报警
celsiusToFahrenheit("热死了");        // ❌ 参数类型不匹配
celsiusToFahrenheit(undefined);       // ❌ 同上

在 VSCode 里把鼠标悬停在 t1 上，编辑器会显示 const t1: number —— 这就是类型推断 + IDE 智能提示，是 TS 开发体验的核心。

本章小结：TS = JS + 类型系统；tsc 负责「检查 + 擦除」，类型零运行时开销；装好 Node 和 tsc 后，tsc 文件名.ts 编译、npx tsx 文件名.ts 直接跑。练习：自己写一个计算圆面积、矩形面积的程序，参数全部标注类型，并故意传错类型观察报错。
02

基础类型与类型系统

基础篇约 3 小时前置：第 1 章

学习目标

  • 掌握全部基础类型：原始类型、数组、元组、any/unknown/never/void
  • 理解类型推断与类型注解的区别，知道何时该写注解
  • 掌握联合类型、字面量类型、类型别名、类型断言

2.1 原始类型

TS 的原始类型和 JS 一一对应，只是可以显式标注。逐个过一遍：

// number —— 所有数字（整数、小数、负数、NaN、Infinity）
let age: number = 30;
let price: number = 9.99;
let notANumber: number = NaN;

// string —— 文本，支持单引号、双引号、模板字符串
let name: string = "Alice";
let greeting: string = `你好，${name}！`;

// boolean —— 布尔
let isDone: boolean = false;

// bigint —— 大整数（超出 number 安全范围时用），字面量末尾加 n
let big: bigint = 9007199254740993n;

// symbol —— 唯一标识
const key: symbol = Symbol("id");

// null 与 undefined —— 两种「空」
let a: null = null;          // 明确表示「这里没有值」
let b: undefined = undefined; // 表示「变量还没定义」
let c: undefined;             // 没赋值时，类型就是 undefined
🧠 基本原理：为什么 null 和 undefined 要分开

在 JS 里它们语义不同：null 是「开发者主动放的空」，undefined 是「系统给的未定义」。TS 保留了这个区分，并在严格模式下（第 9 章讲）强制你处理它们——这是 TS 消灭「半个 bug 王国」的关键设计：很多线上崩溃都源于「某个值其实是 null，但代码以为它有值」。

2.2 类型推断 vs 类型注解

给变量写类型有两条路，TS 都支持：

// ① 类型注解（type annotation）：显式写出类型
let count: number = 42;

// ② 类型推断（type inference）：让 TS 从初始值自动推导
let count2 = 42;   // TS 自动推断 count2 是 number

// 推断是默认行为，且推荐优先使用
let message = "hello";      // message: string
let isOk = true;            // isOk: boolean
const pi = 3.14;            // pi: 3.14（const 推断出字面量类型！）
🧠 基本原理：推断的规则
  • let 声明：根据初始值推断「宽」类型（let x = 1 → number，之后可以改成 2、3）。
  • const 声明：推断「窄」的字面量类型（const x = 1 → 1，因为它永远不变）。
  • 函数返回值：根据 return 语句推断（function f() { return "a" } → 返回类型 string）。
  • 经验法则：能推断就不写注解；函数参数必须写（TS 无法凭空知道调用方会传什么）；希望「限制」变量只能是什么值时写注解。

2.3 数组与元组

// 数组的两种写法，完全等价
let nums1: number[] = [1, 2, 3];
let nums2: Array<number> = [1, 2, 3];   // 泛型写法，第 6 章细讲

let names: string[] = ["a", "b"];
let matrix: number[][] = [[1, 2], [3, 4]];   // 二维数组

// 数组声明后不能塞别的类型
nums1.push("x");   // ❌ 参数类型 "string" 不能赋值给 "number"

// 元组 tuple：固定长度、每个位置类型固定 —— 常用于「成对数据」
let point: [number, number] = [10, 20];   // 坐标
let httpStatus: [number, string] = [200, "OK"];

// 只读数组：只允许读，不允许改 —— 函数传参防篡改利器
let ro: readonly number[] = [1, 2, 3];
ro.push(4);        // ❌ 只读数组不能 push
// 只读元组
let rc: readonly [number, string] = [200, "OK"];
🎯 应用场景
  • 数组：任何「一堆同类型数据」——用户列表、日志行、坐标数组。
  • 元组：CSV 解析结果、键值对列表、API 的 [状态码, 消息] 返回。
  • 只读数组：把内部数据暴露给外部时，防止被意外修改。

2.4 特殊类型：any / unknown / never / void

// any —— 「不管类型」，TS 的逃生舱。能不用就不用！
let anything: any = 42;
anything = "改成字符串也行";
anything.toUpperCase();   // 不报错，但运行时可能崩 —— 类型保护完全失效

// unknown —— 安全的 any：它「不知道是什么」，但逼你先检查再用
let input: unknown = JSON.parse('{"a":1}');
input.a;                  // ❌ unknown 类型上不能访问属性，必须先收窄
if (typeof input === "object" && input !== null) {
  // 此时 input 收窄为 object，可以安全访问
  console.log("是一个对象");
}

// never —— 「永远不可能的值」：函数抛异常、无限循环、穷尽检查
function fail(msg: string): never {
  throw new Error(msg);    // 抛异常的函数永远不会正常返回
}
function infinite(): never {
  while (true) {}          // 死循环也不会返回
}

// void —— 「没有返回值」
function log(message: string): void {
  console.log(message);    // 没有 return，或 return undefined
}
🧠 基本原理：四个特殊类型的心智模型
  • any：关闭检查。危险在于「传染」——任何碰过 any 的变量都会失去类型，最好当成「这里有个类型漏洞」来对待。
  • unknown：any 的安全替代。它代表「未知值」，TS 强制你先做类型收窄（typeof、instanceof 等）才能用。处理 JSON.parse、用户输入、第三方数据时优先用它。
  • never：空集。它是所有类型的子类型，可以赋给任何类型；但没有任何值可以赋给它（除了 never 本身）。在 switch 穷尽检查中价值巨大（第 7 章演示）。
  • void：函数「不返回有意义的值」。用于事件处理函数、日志函数等。

2.5 联合类型、字面量类型与类型别名

// 联合类型（Union）：一个值「可能是 A 或 B」，用 | 连接
let id: string | number = 101;    // 数字 ID
id = "A-101";                     // 换成字符串 ID 也行
id = true;                        // ❌ boolean 不在联合里

// 字面量类型：把「具体的值」当类型用 —— 枚举式的约束
let direction: "left" | "right" | "up" | "down" = "left";
direction = "sideways";           // ❌ 不在可选值里

// 类型别名（type）：给一组类型起名字，可复用
type Direction = "left" | "right" | "up" | "down";
type ID = string | number;

let d: Direction = "up";          // 用别名声明
function move(dir: Direction) { /* ... */ }

// 交叉类型（Intersection）：同时满足 A 和 B，用 & 连接
type Named = { name: string };
type Aged = { age: number };
type Person = Named & Aged;       // 既有 name 又有 age
const p: Person = { name: "Tom", age: 20 };
🎯 应用场景
  • 联合类型：接口返回「成功对象 | 失败对象」、函数参数「数字 ID | 字符串 ID」、表单字段「数字 | 空」。
  • 字面量类型：按钮状态 "primary" | "secondary" | "danger"、排序方向、路由名 —— 比字符串散落各处安全得多。
  • 类型别名：把业务类型收敛到一处定义，全项目复用。

2.6 类型断言（as）与非空断言（!）

// 类型断言：你比编译器更清楚，让它「别管了，按我说的来」
// 注意：断言不改变运行时，只是欺骗类型系统 —— 慎用！
const el = document.getElementById("app") as HTMLDivElement;
const value: unknown = "123";
const len = (value as string).length;   // 5

// 非空断言：告诉 TS 「这个值绝对不是 null/undefined」
function getConfig(): string | null {
  return Math.random() > 0.5 ? "production" : null;
}
const config = getConfig()!;            // 我保证它不是 null
console.log(config.toUpperCase());      // 不报错（但运行时要真不为 null！）
⚠️ 使用红线

as 和 ! 都是「绕开类型检查」，滥用会让 TS 失去意义。经验法则：能用类型收窄（typeof/判断）解决，就不要用断言；用断言时在旁边注释原因。

2.7 实际案例：商品购物车的数据建模

💻 案例：把「购物车」这个业务场景完整用类型描述出来
// cart.ts —— 购物车案例
// 商品分类：字面量联合类型，防止拼错
type Category = "电子产品" | "图书" | "食品" | "服装";

// 商品：number[] 不行，这里用元组和别名
type Sku = string;   // 库存单位编号，如 "SKU-001"

type Product = {
  sku: Sku;
  name: string;
  price: number;
  category: Category;
  stock: number;
  onSale?: boolean;        // 可选属性：有些商品没有折扣
};

// 购物车条目：商品 + 数量
type CartItem = {
  product: Product;
  quantity: number;
};

// 购物车结算
function checkout(items: CartItem[]): number {
  return items.reduce((total, item) => {
    const price = item.product.onSale ? item.product.price * 0.8 : item.product.price;
    return total + price * item.quantity;
  }, 0);
}

// 使用：类型错误会被立刻抓住
const phone: Product = {
  sku: "SKU-001",
  name: "智能手机",
  price: 2999,
  category: "电子产品",
  stock: 50,
  onSale: true,
};
const book: Product = {
  sku: "SKU-002",
  name: "《TS 教程》",
  price: 99,
  category: "图书",     // 拼成 "图出" 会立刻报错 ❌
  stock: 200,
};

const cart: CartItem[] = [
  { product: phone, quantity: 2 },
  { product: book, quantity: 1 },
];

console.log(`应付：¥${checkout(cart).toFixed(2)}`);
// 计算：2999*0.8*2 + 99*1 = 4897.40
本章小结：原始类型 + 数组元组是地基；any 少用、unknown 多用；联合/字面量/别名是日常建模三件套；断言是最后手段。练习：给「图书借阅系统」建模——书（ISBN、书名、作者、价格、可借数量）、借阅记录（借书人、书、借出/归还时间）、函数「计算逾期罚款」。
03

接口与对象类型

基础篇约 2.5 小时前置：第 2 章

学习目标

  • 熟练用 interface 描述对象「长什么样」
  • 掌握可选属性、只读属性、索引签名、接口继承
  • 理解 interface 与 type 的区别与选型原则

3.1 什么是接口

接口（interface）是 TS 描述「一个对象应该有哪些字段、每个字段什么类型」的语法。它不产生任何运行时代码，纯粹是编译期的「形状描述」。写接口相当于给对象画了一张「蓝图」或「合同」。

// 定义一个 User 接口：任何符合这个形状的对象都是 User
interface User {
  id: number;
  name: string;
  email: string;
}

// 使用：变量的类型标注为 User，就必须符合形状
const u1: User = { id: 1, name: "张三", email: "zhang@example.com" };
const u2: User = { id: 2, name: "李四" };         // ❌ 缺少 email
const u3: User = { id: 3, name: "王五", email: "w@e.com", age: 20 }; // ❌ 多了 age（多余属性报错）

// 把对象作为参数传入
function sendEmail(user: User): void {
  console.log(`发送邮件给 ${user.name} <${user.email}>`);
}
🧠 基本原理：结构化类型（鸭子类型）

TS 判断「一个对象是不是 User」，不看它来自哪个类，只看形状是否匹配——「只要长得像鸭子、叫起来像鸭子，它就是鸭子」。所以：

  • 用字面量直接创建的对象、类 new 出来的实例、JSON 解析出来的数据，只要字段类型对得上，都能当作 User 用。
  • 这也意味着接口之间天然兼容：A 接口的对象可以赋给 B 接口的变量（如果 B 需要的字段 A 都有）。
// 形状兼容：这个对象虽然没标 User，但形状一样，就能用
const someone = { id: 9, name: "老张", email: "z@x.com" };

// 多余属性检查只在「字面量直接赋值」时触发
sendEmail({ id: 1, name: "a", email: "b@c.com", vip: true }); // ❌ 字面量多了 vip
const withVip = { id: 1, name: "a", email: "b@c.com", vip: true };
sendEmail(withVip);   // ✅ 先存进变量再传，多余属性被忽略

💻 案例：电商订单的接口分层设计
// order.ts —— 接口驱动的订单系统
// 基础：金额单位统一用「分」避免浮点误差
interface OrderLine {
  sku: string;
  title: string;
  unitPriceCents: number;
  quantity: number;
}

interface Address {
  province: string;
  city: string;
  detail: string;
  phone: string;
  readonly createdAt?: string;
}

// 状态用字面量联合，杜绝「订单状态拼错」
type OrderStatus = "pending" | "paid" | "shipped" | "completed" | "cancelled";

// 主订单：继承公共字段 + 业务字段
interface Order {
  id: string;
  lines: OrderLine[];
  shipTo: Address;
  status: OrderStatus;
  readonly createdAt: string;
  totalCents?: number;        // 未结算时为 undefined
}

// 函数：结算订单（参数是接口，返回结算信息）
function settle(order: Order): { orderId: string; totalCents: number } {
  const totalCents = order.lines.reduce(
    (sum, l) => sum + l.unitPriceCents * l.quantity, 0
  );
  order.status = "paid";      // 更新状态
  return { orderId: order.id, totalCents };
}

// 使用
const myOrder: Order = {
  id: "ORD-2026-0001",
  lines: [
    { sku: "SKU-1", title: "机械键盘", unitPriceCents: 39900, quantity: 1 },
    { sku: "SKU-2", title: "鼠标垫", unitPriceCents: 2900, quantity: 2 },
  ],
  shipTo: { province: "广东", city: "深圳", detail: "科技园路 1 号", phone: "13800000000" },
  status: "pending",
  createdAt: "2026-08-18T10:00:00Z",
};

const result = settle(myOrder);
console.log(`订单 ${result.orderId} 实付 ¥${(result.totalCents / 100).toFixed(2)}`);
// 输出：订单 ORD-2026-0001 实付 ¥457.00
本章小结：interface 描述「形状」，鸭子类型让任意形状匹配的对象都能用；可选/只读/索引签名/继承覆盖了日常建模 90% 需求；对象形状用 interface，类型运算用 type。练习：为「图书馆」建模——Book、Member、Loan 三个接口，Loan 引用 Book 和 Member，再写一个借书函数检查可借数量。

4.1 函数的基本类型标注

// 普通函数：参数标类型，返回值标类型
function add(a: number, b: number): number {
  return a + b;
}

// 函数表达式：给变量标注「函数类型」
const multiply: (a: number, b: number) => number = (a, b) => a * b;

// 用 type 给函数类型起名字 —— 复用方便
type MathFn = (a: number, b: number) => number;
const divide: MathFn = (a, b) => a / b;

// 函数作为参数（回调）
function compute(op: MathFn, x: number, y: number): number {
  return op(x, y);
}
console.log(compute(add, 10, 5));        // 15
console.log(compute(divide, 10, 5));     // 2

// 无返回值用 void
function logMsg(msg: string): void {
  console.log(msg);
}
🧠 基本原理：参数类型为什么必须写，返回值可以推断

编译器看不到「调用方会传什么」，所以参数类型无法推断，必须标注（否则默认 any，等于没检查）。返回值则可以从 return 语句推断，但显式写出相当于「承诺」，防止实现改坏了没人发现。团队规范通常要求：参数必写、返回值建议写。

4.2 可选参数、默认参数、剩余参数

// 可选参数：? 结尾，调用时可省略
function greet(name: string, greeting?: string): string {
  return greeting ? `${greeting}, ${name}!` : `你好, ${name}!`;
}
greet("张三");                 // 你好, 张三!
greet("张三", "Good morning"); // Good morning, 张三!

// 默认参数：带 = 值，比可选参数更常用（自动兜底）
function greet2(name: string, greeting = "你好"): string {
  return `${greeting}, ${name}!`;
}

// 注意规则：可选/默认参数必须放在必选参数后面！
// function bad(a?: number, b: number) {}  // ❌

// 剩余参数：...rest 收集多余参数，一定是数组
function sumAll(...nums: number[]): number {
  return nums.reduce((s, n) => s + n, 0);
}
sumAll(1, 2, 3, 4, 5);   // 15

// 回调函数中的参数类型会自动推断
const list = [1, 2, 3, 4];
list.filter(n => n % 2 === 0);   // n 自动推断为 number，不用写
list.map((n, index) => ({ n, index }));  // 参数和返回值都有提示

4.3 函数重载（Overload）

同一个函数，根据参数的类型/数量不同，返回不同的类型。写法：先列多个「重载签名」，最后写一个「实现签名」。

// 场景：format 函数 —— 传 Date 返回 "2026-08-18"；传 string 原样返回；传 number 转字符串
function format(input: Date): string;          // 重载签名 1
function format(input: string): string;        // 重载签名 2
function format(input: number): string;        // 重载签名 3
function format(input: Date | string | number): string {  // 实现签名（对调用方不可见）
  if (input instanceof Date) {
    return `${input.getFullYear()}-${String(input.getMonth() + 1).padStart(2, "0")}-${String(input.getDate()).padStart(2, "0")}`;
  }
  return String(input);
}

const d = format(new Date());   // "2026-08-18" 类型是 string
const s = format("abc");        // "abc"
const n = format(123);          // "123"
🧠 基本原理：为什么要有重载

实现签名里的参数类型是联合类型，如果只写实现签名，调用方看到的返回类型也是「笼统的 string」。重载让 TS 能根据你传入的参数类型，精确给出对应的返回类型，IDE 提示也更准确。注意：重载签名必须能互相兼容，且实现签名对调用方隐藏。

const counter: Counter = {

💻 案例：防抖（debounce）+ 参数校验 —— 前端高频场景
// utils.ts
// ① 防抖：搜索框输入、窗口 resize 等高频事件，最后一次才执行
function debounce<T extends (...args: never[]) => void>(
  fn: T,
  delay = 300
): (...args: Parameters<T>) => void {
  let timer: ReturnType<typeof setTimeout> | undefined;
  return (...args) => {
    if (timer) clearTimeout(timer);
    timer = setTimeout(() => fn(...args), delay);
  };
}
// 上面用了泛型 T 和工具类型（第 6-7 章详解），现在先会用：
// 用法 —— 原函数是什么签名，防抖后的函数就是什么签名，类型自动保留

// ② 参数校验函数
type Validator = (value: unknown) => string | null;   // 返回错误信息或 null

const required: Validator = (value) =>
  value === "" || value === null || value === undefined ? "该字段必填" : null;

const isEmail: Validator = (value) =>
  typeof value === "string" && /\S+@\S+\.\S+/.test(value) ? null : "邮箱格式不正确";

// ③ 表单校验器：一次校验多个字段
interface Rule { field: string; validators: Validator[] }
function validate(rules: Rule[], data: Record<string, unknown>): Record<string, string> {
  const errors: Record<string, string> = {};
  for (const rule of rules) {
    for (const v of rule.validators) {
      const err = v(data[rule.field]);
      if (err) { errors[rule.field] = err; break; }
    }
  }
  return errors;
}

// ④ 使用
const formData = { username: "", email: "bad-email" };
const rules: Rule[] = [
  { field: "username", validators: [required] },
  { field: "email", validators: [required, isEmail] },
];
console.log(validate(rules, formData));
// { username: "该字段必填", email: "邮箱格式不正确" }
本章小结：参数必标注、返回值可推断；默认参数 > 可选参数；重载解决「同函数不同类型返回」；回调自动推断是日常最爽体验。练习：写一个 once 函数（包装任意函数，只能调用一次），并给它加上完整类型。

5.1 类的基本写法

// TS 的类 = JS 的类 + 类型标注（字段、方法、访问控制）
class Person {
  // 字段声明 + 类型（这是 TS 新增的，JS 没有）
  name: string;

  // 构造函数：参数标注类型，给字段赋值

    this.name = name;
    this.age = age;

5.2 访问修饰符：public / private / protected

class BankAccount {
  // public：默认，任何人都能访问
  public owner: string;

  // private：只有「本类内部」能访问（子类也不行）
  private balance: number;

  // protected：本类 + 子类内部能访问，外部不行
  protected accountNo: string;

  constructor(owner: string, accountNo: string, initBalance: number) {
    this.owner = owner;
    this.accountNo = accountNo;
    this.balance = initBalance;
  }

  public deposit(amount: number): void {
    this.balance += amount;      // 内部可以访问 private
  }

  public getBalance(): number {
    return this.balance;
  }
}

const acc = new BankAccount("张三", "6222 0000", 1000);
acc.owner = "李四";              // ✅ public 可改
acc.getBalance();                // ✅ 通过公开方法读取
// acc.balance = 9999;           // ❌ private 外部不可访问
// acc.accountNo;                // ❌ protected 外部不可访问
⚠️ 关键认知：修饰符只在编译期有效

编译成 JS 后，private/protected 会被擦除，变成普通属性——运行时照样能访问。TS 的封装是「开发规范护栏」，不是「安全加密」。真正要防运行时篡改，得用 JS 的 #privateField 语法（TS 也支持）。

5.3 readonly 与 static

class Config {

  readonly appName: string;

  // static：属于「类本身」而不是实例，无需 new 就能访问
  static version = "1.0.0";

  // 私有静态：只有类内部能用（常用于单例模式，第 14 章）
  private static instance: Config | null = null;

  constructor(appName: string) {
    this.appName = appName;
  }

  static getVersion(): string {
    return Config.version;
  }
}

console.log(Config.version);       // 1.0.0 —— 不用 new
console.log(Config.getVersion());  // 1.0.0
const c = new Config("MyApp");
// c.appName = "Other";           // ❌ readonly 不可改
// Config.instance;               // ❌ private static 外部不可访问

5.4 继承、抽象类、实现接口

// ① 继承：子类 extends 父类，用 super 调父类构造函数
class Student extends Person {
  grade: number;
  constructor(name: string, age: number, grade: number) {
    super(name, age);        // 必须先 super()
    this.grade = grade;
  }
  // 重写父类方法
  introduce(): string {
    return super.introduce() + `，读 ${this.grade} 年级`;
  }
}
const stu = new Student("小明", 12, 6);
console.log(stu.introduce());   // 我是 小明，今年 12 岁，读 6 年级

// ② 抽象类：定义「骨架」，细节交给子类。不能 new，只能被继承
abstract class Shape {
  abstract area(): number;      // 抽象方法：只声明，不实现

  describe(): string {          // 普通方法：可以有实现
    return `面积：${this.area()}`;
  }
}

class Circle extends Shape {
  constructor(private radius: number) { super(); }
  area(): number { return Math.PI * this.radius ** 2; }
}

class Rectangle extends Shape {
  constructor(private w: number, private h: number) { super(); }
  area(): number { return this.w * this.h; }
}

const shapes: Shape[] = [new Circle(2), new Rectangle(3, 4)];
shapes.forEach(s => console.log(s.describe()));
// 面积：12.566370614359172
// 面积：12

// ③ 实现接口：class implements 接口，必须实现接口里所有成员
interface Flyable {
  fly(): void;
}
interface Swimmable {
  swim(): void;
}
class Duck implements Flyable, Swimmable {
  fly() { console.log("飞起来了"); }
  swim() { console.log("游起来了"); }
}
🧠 基本原理：implements vs extends
  • extends（继承）：获得父类的实现代码，可以复用、重写。是一个「是」的关系（狗是一种动物）。
  • implements（实现）：只要求「形状符合」，不获得任何代码。是一个「能」的关系（鸭子能飞、能游）。
  • 实际项目更推荐「组合优先」：多用接口定义能力 + 组合，少建深层继承链。

5.5 实际案例：银行账户系统（完整封装）

💻 案例：账户体系 —— 私有字段 + 抽象类 + 多态
// bank.ts
abstract class Account {
  constructor(
    protected readonly accountNo: string,   // 子类可读，外部不可改
    protected balance: number               // 子类可读写
  ) {}

  abstract get type(): string;   // 抽象属性：子类必须实现

  deposit(amount: number): void {
    if (amount <= 0) throw new Error("存款金额必须大于 0");
    this.balance += amount;
  }

  withdraw(amount: number): void {
    if (amount > this.balance) throw new Error("余额不足");
    this.balance -= amount;
  }

  getBalance(): number {
    return this.balance;
  }
}

// 储蓄账户：有利率
class SavingsAccount extends Account {
  constructor(accountNo: string, balance: number, private rate: number) {
    super(accountNo, balance);
  }
  get type(): string { return "储蓄账户"; }
  applyInterest(): void {
    this.balance += this.balance * this.rate;
  }
}

// 信用卡账户：允许透支（balance 可为负）
class CreditAccount extends Account {
  constructor(accountNo: string, limit: number) {
    super(accountNo, 0);
    this.limit = limit;
  }
  private limit: number;
  get type(): string { return "信用卡"; }
  withdraw(amount: number): void {          // 重写：多态
    if (amount > this.balance + this.limit) throw new Error("超出信用额度");
    this.balance -= amount;
  }
}

// 使用
const savings = new SavingsAccount("SAV-001", 10000, 0.02);
savings.deposit(5000);
savings.applyInterest();
console.log(`${savings.type} 余额：${savings.getBalance()}`);  // 储蓄账户 余额：15300

6.1 为什么需要泛型（动机）

写一个「返回数组第一个元素」的函数，你会怎么写？

// 方案 A：any —— 能跑，但类型全丢了，用起来毫无提示
function first(arr: any[]): any {
  return arr[0];
}
const x = first([1, 2, 3]);     // x 是 any，之后调用 x.toFixed() 也不报错

// 方案 B：写死 number —— 只适用于一种类型
function firstNum(arr: number[]): number {
  return arr[0];
}

// 方案 C：泛型 —— 类型参数化：调用时决定类型，并且「进去什么、出来什么」被绑定
function first<T>(arr: T[]): T {
  return arr[0];
}
const a = first([1, 2, 3]);      // a: number
const b = first(["x", "y"]);     // b: string
const c = first([{ id: 1 }, { id: 2 }]);  // c: { id: number }
// 传入和返回的类型一致，TS 自动推断 T
🧠 基本原理：泛型 = 类型的「参数化」

普通函数参数化值：function add(a, b)。泛型参数化类型：function first<T>(arr: T[])。<T> 是一个「类型占位符」，调用时被具体类型替换（如 number、string），替换后整个函数的类型关系（参数与返回类型一致）依然被严格检查。它把「类型安全」和「通用性」同时保住了。

6.2 泛型函数与泛型接口、泛型类

// 泛型函数：显式指定类型参数（调用时可省略，让 TS 推断）
function identity<T>(value: T): T {
  return value;
}
identity<number>(42);   // 显式
identity("hello");      // 推断为 string

// 泛型接口
interface Box<T> {
  value: T;
}
const numBox: Box<number> = { value: 1 };
const strBox: Box<string> = { value: "a" };

// 泛型类：经典例子 —— 通用栈
class Stack<T> {
  private items: T[] = [];
  push(item: T): void { this.items.push(item); }
  pop(): T | undefined { return this.items.pop(); }
  get size(): number { return this.items.length; }
}

const numStack = new Stack<number>();
numStack.push(1);
numStack.push(2);
// numStack.push("x");   // ❌ 只能放 number
console.log(numStack.pop());   // 2

const strStack = new Stack<string>();
strStack.push("a");            // 各自独立，互不影响

6.3 泛型约束（extends）

// 问题：直接写 arr[0].length，TS 会报错 —— T 不一定有 length
// function getLength<T>(arr: T[]): number { return arr[0].length; }  // ❌

// 解决：用 extends 约束 T 必须满足某个形状
interface HasLength {
  length: number;
}

function getLength<T extends HasLength>(value: T): number {
  return value.length;    // 现在安全了：T 保证有 length
}
getLength("hello");        // 5  （string 有 length）
getLength([1, 2, 3]);      // 3  （数组有 length）
// getLength(42);          // ❌ number 没有 length

// 约束到「对象键」：keyof 提取键的联合类型
function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}
const user = { id: 1, name: "Tom" };
getProperty(user, "name");    // string
getProperty(user, "id");      // number
// getProperty(user, "age");  // ❌ "age" 不是 user 的键

7.1 类型守卫与类型收窄

联合类型的值，在「还没确认是哪个分支」前，只能使用所有分支共有的能力。确认的过程叫类型收窄（narrowing），收窄用的判断语句叫类型守卫（type guard）。

type Result = { ok: true; data: string } | { ok: false; error: string };

function handle(r: Result) {
  if (r.ok) {
    // 这里 r 被收窄为 { ok: true; data: string }，可以安全用 data
    console.log(r.data.toUpperCase());
  } else {
    // 这里 r 是 { ok: false; error: string }
    console.error(r.error);
  }
}

// 四种常用守卫：
// ① typeof —— 基础类型判断
function pad(n: string | number): string {
  if (typeof n === "number") return String(n).padStart(2, "0");
  return n.padStart(2, "0");
}

// ② instanceof —— 类实例判断
function describe(x: Date | string): string {
  if (x instanceof Date) return `日期：${x.toISOString()}`;
  return `文本：${x}`;
}

// ③ in —— 对象属性判断
interface Fish { swim(): void }
interface Bird { fly(): void }
function move(animal: Fish | Bird) {
  if ("swim" in animal) animal.swim();   // in 能区分对象形状
  else animal.fly();
}

// ④ 自定义类型谓词：is 关键字 —— 复杂判断封装成可复用守卫
function isFish(animal: Fish | Bird): animal is Fish {
  return "swim" in animal;
}
const pets: (Fish | Bird)[] = [];
pets.filter(isFish).forEach(f => f.swim());   // filter 后自动收窄为 Fish[]
🧠 基本原理：可辨识联合 + 穷尽检查

给联合的每个分支加一个「判别字段」（如 ok、type、kind），switch 后 TS 能精确收窄，配合 never 做穷尽检查——以后加新分支忘了处理，编译器立刻报错：

type Shape =
  | { kind: "circle"; radius: number }
  | { kind: "square"; side: number }
  | { kind: "triangle"; base: number; height: number };

function area(s: Shape): number {
  switch (s.kind) {
    case "circle":   return Math.PI * s.radius ** 2;
    case "square":   return s.side ** 2;
    case "triangle": return (s.base * s.height) / 2;
    default:
      // 如果以后加了新 Shape 分支却没处理，s 会变成 never，这里报错
      const _exhaustive: never = s;
      return _exhaustive;
  }
}

7.2 keyof / typeof / 索引访问类型

// keyof T：取对象所有键的联合类型
interface Config { url: string; timeout: number; retries: number }
type ConfigKey = keyof Config;    // "url" | "timeout" | "retries"

// typeof 值：把「值」变成「类型」（只能用于变量/对象）
const settings = { url: "/api", timeout: 5000, retries: 3 };
type SettingsType = typeof settings;   // { url: string; timeout: number; retries: number }

// 索引访问类型 T[K]：取某个键对应的值类型
type UrlType = Config["url"];             // string
type MixedType = Config["url" | "timeout"];  // string | number
type AnyKey = Config[keyof Config];       // string | number —— 所有值类型的联合

// 组合使用：动态安全地访问对象
function pluck<T, K extends keyof T>(obj: T, keys: K[]): T[K][] {
  return keys.map(k => obj[k]);
}
pluck(settings, ["url", "timeout"]);   // (string | number)[]

7.3 条件类型与 infer

// 条件类型：T extends U ? X : Y —— 类型的 if/else
type IsString<T> = T extends string ? "是字符串" : "不是字符串";
type A = IsString<"hello">;   // "是字符串"
type B = IsString<42>;        // "不是字符串"

// 分布式条件类型：联合类型会「拆开逐个判断再合并」
type ToArray<T> = T extends unknown ? T[] : never;
type C = ToArray<string | number>;   // string[] | number[]（拆开处理）

// infer：在 extends 里「猜」出一个类型 —— 类型编程的瑞士军刀
// 手写 ReturnType：猜函数返回类型
type MyReturnType<T extends (...args: any) => any> =
  T extends (...args: any) => infer R ? R : never;
type D = MyReturnType<() => string>;   // string

// 手写 Parameters：猜参数元组
type MyParameters<T extends (...args: any) => any> =
  T extends (...args: infer P) => any ? P : never;
type E = MyParameters<(a: number, b: string) => void>;   // [number, string]

// 经典：解包 Promise
type Unwrap<T> = T extends Promise<infer U> ? Unwrap<U> : T;
type F = Unwrap<Promise<Promise<number>>>;   // number（递归解包）

7.4 映射类型与模板字面量类型

// 映射类型：遍历键，逐个改造 —— 前面手写 Partial/Readonly 就是它
// 进阶：+? / -? 控制可选，as 重映射键
type Nullable<T> = { [K in keyof T]: T[K] | null };        // 值加 null

type EventMap<T> = {
  [K in keyof T as `on${Capitalize<string & K>}`]: (payload: T[K]) => void;

}

11.1 什么是装饰器

装饰器（Decorator）是「给类、方法、属性附加额外行为的语法」。不改变代码本身，而是包装它：记录日志、加权限校验、绑定 this、注入依赖…… 它是 AOP（面向切面编程）思想的实现。

// 先启用（装饰器目前是实验特性，需要 tsconfig 打开）：
// { "compilerOptions": { "experimentalDecorators": true } }

// 最直观的例子：类方法装饰器 —— 自动记录日志
function log(target: any, propertyKey: string, descriptor: PropertyDescriptor) {
  const original = descriptor.value;
  descriptor.value = function (...args: any[]) {
    console.log(`[LOG] 调用 ${propertyKey}，参数：`, args);
    const result = original.apply(this, args);
    console.log(`[LOG] ${propertyKey} 返回：`, result);
    return result;
  };
}

class Calculator {
  @log            // 用法：@装饰器 写在方法上面
  add(a: number, b: number): number {
    return a + b;
  }
}

const calc = new Calculator();
calc.add(2, 3);
// [LOG] 调用 add，参数： [ 2, 3 ]
// [LOG] add 返回： 5
🧠 基本原理：装饰器是怎么生效的
  • 方法装饰器接收 3 个参数：target（类的原型）、propertyKey（方法名）、descriptor（属性描述符）。
  • 本质：装饰器函数在类定义时执行，通过替换 descriptor.value 包装原方法 —— 运行时「原方法被包了一层」。用户代码无感知，行为却被增强。
  • 执行顺序：多个装饰器从下往上应用、从上往下执行（洋葱模型）；类装饰器最后执行。

11.2 装饰器工厂（带参数的装饰器）

// 装饰器工厂：外层函数接收参数，返回真正的装饰器
function delay(ms: number) {
  return function (target: any, propertyKey: string, descriptor: PropertyDescriptor) {
    const original = descriptor.value;
    descriptor.value = function (...args: any[]) {
      console.log(`等待 ${ms}ms...`);
      return new Promise(resolve => {
        setTimeout(() => resolve(original.apply(this, args)), ms);
      });
    };
  };
}

class Service {
  @delay(1000)
  fetchData(): string {
    return "数据已返回";
  }
}
// 用法：@delay(1000) —— 工厂函数先跑，返回的装饰器再作用到方法上

  • Angular：@Component()、@Input() 同理。
  • 自己的项目：日志、鉴权、重试、缓存、参数校验 —— 用装饰器把横切逻辑从业务代码里剥离。

11.4 实际案例：装饰器实现「必填校验 + 日志」

💻 案例：给一个表单提交类加校验与日志
// validate.ts —— 参数校验装饰器
function validate(...requiredIndexes: number[]) {
  return function (target: any, propertyKey: string, descriptor: PropertyDescriptor) {
    const original = descriptor.value;
    descriptor.value = function (...args: any[]) {
      for (const idx of requiredIndexes) {
        if (args[idx] === undefined || args[idx] === null || args[idx] === "") {
          throw new Error(`参数 #${idx} 不能为空`);
        }
      }
      return original.apply(this, args);
    };
  };
}

function logMethod(target: any, propertyKey: string, descriptor: PropertyDescriptor) {
  const original = descriptor.value;
  descriptor.value = function (...args: any[]) {
    console.log(`[操作] ${propertyKey}(${args.join(", ")})`);
    const result = original.apply(this, args);
    console.log(`[操作] 完成`);
    return result;
  };
}

class OrderService {
  @logMethod
  @validate(0, 1)   // 第 0、1 个参数必填；多个装饰器从下往上应用
  placeOrder(userId: string, productId: string, quantity = 1) {
    return `订单创建成功：${userId} 购买了 ${productId} x${quantity}`;
  }
}

const svc = new OrderService();
console.log(svc.placeOrder("U-001", "P-888", 2));
// [操作] placeOrder(U-001, P-888, 2)
// [操作] 完成
// 订单创建成功：U-001 购买了 P-888 x2

try {
  svc.placeOrder("", "P-888");   // ❌ 校验装饰器先抛错，日志不执行
} catch (e) {
  console.log("拦截到：", (e as Error).message);
}
本章小结：装饰器 = 不入侵业务代码的「行为包装器」；方法装饰器改 descriptor 是最常用形态；工厂给装饰器加参数；框架路由/注入/校验底层就是它。练习：写一个 @retry(3) 装饰器——方法抛错时自动重试 3 次。

12.1 Promise<T> 与 async/await

// Promise 是泛型：Promise<T> 表示「未来会拿到一个 T」
function fetchUser(): Promise<{ id: number; name: string }> {
  return fetch("/api/user").then(r => r.json());
}

// async 函数：返回值自动包成 Promise，await 自动「拆包」取类型
async function loadUser() {
  const user = await fetchUser();   // user 自动推断为 { id: number; name: string }
  console.log(user.name.toUpperCase());   // ✅ 类型安全
  return user;                      // 返回类型自动推导为 Promise<{...}>
}

// async 函数的三种返回形态
async function a(): Promise<number> { return 42; }          // 直接返回
async function b(): Promise<number> { return Promise.resolve(42); }  // 返回 Promise 会自动展平
async function c(): Promise<void> { console.log("无返回"); } // 不返回
🧠 基本原理：async 的类型「管道」

await 把 Promise<T> 拆成 T；async 函数把返回的 T 包回 Promise<T>（返回 Promise 时自动展平一层）。类型沿着这条管道自动流动，你只需要给「源头」（API 返回）标对类型，后面全是自动的。

12.2 并发：all / allSettled / race

// Promise.all：全部成功才继续，任一失败整体失败；返回「元组类型」
const [users, orders] = await Promise.all([
  fetch("/api/users").then(r => r.json()) as Promise<User[]>,
  fetch("/api/orders").then(r => r.json()) as Promise<Order[]>,
]);
// users: User[]，orders: Order[] —— 类型各归各的

// Promise.allSettled：不抛错，逐个返回成功/失败结果 —— 适合批量任务
const results = await Promise.allSettled([
  uploadFile("a.png"),
  uploadFile("b.png"),
  uploadFile("c.png"),
]);
for (const r of results) {
  if (r.status === "fulfilled") console.log("成功：", r.value);
  else console.log("失败：", r.reason);
}

// Promise.race：谁先完成用谁 —— 超时控制
const data = await Promise.race([
  fetchData(),
  new Promise<never>((_, reject) => setTimeout(() => reject(new Error("超时")), 3000)),
]);

12.3 错误处理与 unknown

// try/catch 里 catch 的 e 默认是 unknown（strict 下）
try {
  await riskyCall();
} catch (e) {
  // e 是 unknown，不能直接 e.message —— 必须先收窄
  if (e instanceof Error) {
    console.error(e.message);          // ✅ 标准错误对象
  } else if (typeof e === "string") {
    console.error(e);                  // ✅ 有些库直接抛字符串
  } else {
    console.error("未知错误", e);
  }
}

// 实战封装：统一的「结果对象」替代 try/catch 满天飞
type AsyncResult<T> = { ok: true; data: T } | { ok: false; error: string };

async function safeCall<T>(fn: () => Promise<T>): Promise<AsyncResult<T>> {
  try {
    return { ok: true, data: await fn() };
  } catch (e) {
    return { ok: false, error: e instanceof Error ? e.message : "未知错误" };
  }
}

const result = await safeCall(() => fetchData());
if (result.ok) {
  console.log(result.data);    // ✅ 类型安全
} else {
  console.error(result.error);
}

12.4 实际案例：带类型 + 超时 + 重试的请求封装

💻 案例：生产级 request 工具
// request.ts
interface RequestOptions {
  timeout?: number;        // 超时毫秒
  retries?: number;        // 失败重试次数
}

async function request<T>(
  url: string,
  options: RequestOptions = {}
): Promise<T> {
  const { timeout = 5000, retries = 1 } = options;

  const attempt = async (): Promise<T> => {
    // 超时 + 请求 竞速
    const res = await Promise.race([
      fetch(url),
      new Promise<never>((_, reject) =>
        setTimeout(() => reject(new Error(`请求超时（${timeout}ms）`)), timeout)
      ),
    ]);
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    return (await res.json()) as T;    // 调用方指定 T，这里断言
  };

  // 重试逻辑
  for (let i = 0; i < retries; i++) {
    try {
      return await attempt();
    } catch (e) {
      if (i === retries - 1) throw e;  // 最后一次失败直接抛
      console.warn(`第 ${i + 1} 次失败，重试中...`);
    }
  }
  throw new Error("不可达");
}

// 使用：类型由你指定，全链路安全
interface Weather { city: string; temp: number }
const weather = await request<Weather>("/api/weather?city=sz", { timeout: 3000, retries: 2 });
console.log(`${weather.city} ${weather.temp}°C`);   // ✅ 有完整类型提示
本章小结：await 拆包、async 打包，类型自动流动；并发场景 all（要全成）、allSettled（容忍失败）、race（要最快）；catch 的 e 是 unknown 要收窄；用 AsyncResult 统一错误处理。练习：写一个 withTimeout 泛型函数（传入 Promise 和毫秒数，超时返回失败）。

// ⑤ 自定义 Hook：泛型让返回值类型精确
export function useLocalStorage<T>(key: string, initial: T) {
  const [value, setValue] = useState<T>(() => {
    const raw = localStorage.getItem(key);
    return raw ? (JSON.parse(raw) as T) : initial;
  });
  const update = (next: T) => {
    setValue(next);
    localStorage.setItem(key, JSON.stringify(next));
  };
  return [value, update] as const;   // 元组：类型是 [T, (next: T) => void]
}

  try {

14.1 类型驱动开发（Type-Driven Development）

核心心法：先定义「数据长什么样」，再写「逻辑怎么处理」。类型先行，实现只是把类型变成代码。

⚙️ 实操步骤（写任何功能都适用）
  1. 定义类型：这个功能的输入、输出、中间状态各是什么形状？（interface / type / 联合）
  2. 定义签名：函数参数、返回类型先写出来。
  3. 编译看错：让 tsc 告诉你哪里对不上 —— 类型即测试。
  4. 填充实现：在类型框架内填逻辑。
  5. 补边界：联合分支、null 情况在类型上就可见，逐个处理。
// 示例：先类型后实现 —— 计算快递运费
// ① 类型先行
type Region = "同城" | "省内" | "跨省";
type Package = { weightKg: number; region: Region; fragile: boolean };
type FeeResult = { feeCents: number; note: string };

// ② 签名先行
function calcShipping(pkg: Package): FeeResult { /* ③ 再填充 */ }

// ③ 实现
function calcShipping(pkg: Package): FeeResult {
  let feeCents = pkg.weightKg * 1000;
  if (pkg.region === "同城") feeCents *= 0.8;
  if (pkg.region === "跨省") feeCents *= 1.5;
  if (pkg.fragile) feeCents += 500;
  return { feeCents: Math.round(feeCents), note: `${pkg.region}·${pkg.fragile ? "易碎" : "普通"}` };
}

// ② 策略模式：算法可替换 —— TS 里就是「函数作为策略」
type SortStrategy = (arr: number[]) => number[];
const bubbleSort: SortStrategy = (arr) => [...arr].sort((a, b) => a - b);
const quickSort: SortStrategy = (arr) => [...arr].sort((a, b) => b - a);
function sortWith(arr: number[], strategy: SortStrategy) {
  return strategy(arr);
}
sortWith([3, 1, 2], bubbleSort);   // [1, 2, 3]
sortWith([3, 1, 2], quickSort);    // [3, 2, 1]

// ③ 观察者模式：事件总线
type Listener<T> = (payload: T) => void;
class EventBus {
  private listeners = new Map<string, Listener<unknown>[]>();
  on<T>(event: string, fn: Listener<T>) {
    const list = this.listeners.get(event) ?? [];
    list.push(fn as Listener<unknown>);
    this.listeners.set(event, list);
  }
  emit<T>(event: string, payload: T) {
    this.listeners.get(event)?.forEach(fn => (fn as Listener<T>)(payload));
  }
}
const bus = new EventBus();
bus.on<string>("notify", msg => console.log(`收到：${msg}`));
bus.emit("notify", "有人下单了");

14.3 渐进式迁移：把老 JS 项目改成 TS

⚙️ 实操步骤（不伤筋动骨）
  1. 加 tsconfig：先开 allowJs: true、checkJs: false，JS 文件照常编译，项目先「能跑」。
  2. 把 .js 逐个改 .ts：先改入口、公共工具、接口层 —— 收益最高的文件优先。
  3. 逐步开 strict：先 strict: false，再分项打开 strictNullChecks 等，逐个修复报错。
  4. 补类型声明：第三方库装 @types，内部遗留模块写 .d.ts 兜底。
  5. 最后收紧：关掉 allowJs，strict 全开，tsc --noEmit 进 CI。
⚠️ 迁移红线

别一次性全量迁移。每改一个文件就跑一次测试、提交一次。用 // @ts-nocheck 给暂时没迁完的文件免责，但要限期清理。

// ===== src/commands.ts =====
import { LedgerDB, Record, Summary, AddInput, Category } from "./types";

export function addRecord(db: LedgerDB, input: AddInput): Record {
  const amountCents = Math.round(input.amount * 100);
  if (amountCents <= 0) throw new Error("金额必须大于 0");
  const record = {
    id: crypto.randomUUID(),
    amountCents,
    category: input.category,
    note: input.note,
    createdAt: new Date().toISOString(),
  };
  db.records.push(record);
  return record;
}

export function deleteRecord(db: LedgerDB, id: string): boolean {
  const idx = db.records.findIndex(r => r.id === id);
  if (idx === -1) return false;
  db.records.splice(idx, 1);
  return true;
}

export function summarize(db: LedgerDB): Summary {
  const totalCents = db.records.reduce((s, r) => s + r.amountCents, 0);
  const byCategory: Partial<Record<Category, number>> = {};
  for (const r of db.records) {
    byCategory[r.category] = (byCategory[r.category] ?? 0) + r.amountCents;
  }
  return { totalCents, byCategory, count: db.records.length };
}

export function formatSummary(s: Summary): string {
  const lines = Object.entries(s.byCategory)
    .sort((a, b) => b[1] - a[1])
    .map(([cat, cents]) => `  ${cat.padEnd(4)} ¥${((cents ?? 0) / 100).toFixed(2)}`);
  return [
    `共 ${s.count} 笔，总支出 ¥${(s.totalCents / 100).toFixed(2)}`,
    ...lines,
  ].join("\n");
}
